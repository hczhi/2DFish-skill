# 错误与提示文案：照抄件

这一份和 `doc/ppt-prompts.md` 一样是**照抄件**。里面每一句话都要**一个字不改地搬过去**，包括括号里那半句"不然会怎样"。

为什么文案要进交接文档 —— 这个模块的每一次失败都花过真钱（一份稿子是十几次 AI 调用，配图是按张付的），而**同一个状态码下有五六种完全不同的成因，解法互相冲突**：

| 他看到的 | 真实成因 | 该做什么 | 做错了会怎样 |
| --- | --- | --- | --- |
| "生成失败，请重试" | 思维链把 `max_tokens` 吃完了 | 换一个不带思维链的模型 | 一路重试，每次真扣一次额度，永远不会好 |
| "生成失败，请重试" | `finish_reason=length` | 拆短提纲 | 同上 |
| "生成失败，请重试" | 他自己在后台勾了"关思维链"但上游不照办 | 换模型（那个勾选框对这条接入点无效） | 反复回后台核那个已经勾上的开关 |
| "生成失败，请重试" | 页序在这期间变过（409） | 刷新页面 | 重试会把结果落到现在那个页码上 —— 出来是一页正常的幻灯片，只是内容对不上标题 |

合成一句通用错误 = 指错方向。**所以规则是：话术里必须写出真实成因 + 下一步动作 + 这次钱花了没有。**

---

## 0. 五条硬规则

1. **原文照抄，不要重写、不要翻译、不要精简。** 每一句里那半句"（不改的话会怎样）"是判断依据，不是修饰 —— 删掉之后同一句话变成"我们坏了"，而问题在他那边。
2. **一句话回一件事。** 不要把两条校验合成一句（"参数不合法"这种），也不要把两种成因合成一句（上表第 1/2/3 行）。
3. **这次钱花了没有必须写出来。** 花了的一律带 `（这次的 AI 额度已经扣了）` 或 `（这次调用已经花掉了）`；没花的一律带 `这次没改也没花额度`。少了这半句他会按错误的成本估算做下一步决定。
4. **"改了但没存上"和"没改"是两句不同的话。** 前者要加 `画面上是你改过的那句，而库里还是原来那句（拼整份和导出用的都是它）` —— 不说的话他刷新之后以为改动丢了，会再改一遍（而库里其实一直是旧的）。
5. **`notes` / `problems` / `chartNotes` 不是日志，是必须显示在界面上的话。** 它们全部走 200 —— 后端回了、前端不显示，等于这一条约定没生效，而**接口和页面都完全正常**。这一份的 §9、§10 就是这类。

`esc()`：所有塞进 `problems` 的字符串都要 HTML 转义（那些串会进预览页面）—— 不转的话模型写的一段 `<div>` 出现在 problems 里会把面板的结构撑坏。

## 1. 状态码怎么定

统一出口 `sendPptError(res, e, is400, fallback)`：

```
message = e.message || fallback
is400                            → 400 {error: message}
e.name === 'QuotaExceededError'  → 429 {error:'quota_exceeded', remaining:0,
                                        daily_limit:…, app:…, detail: message}
e.name === 'DedicatedChannelError' → 503 {error: message}
其余                              → 500 {error: message}
```

`is400` 由**各端点自己判**（每条路的"参数不对"是不同的错误类），传错方向的后果是明确的错误码，不是静默。

| 错误类 | 从哪来 | 状态码 |
| --- | --- | --- |
| `PageError` | `pageService` / 生成端点的入参校验 | 400 |
| `PageEditError` | `pageEdit` / `canvasEdit` / `regionGuards` / `aiEditService` / `aiRemakeService` | 400 |
| `PlanError` | `planService` | 400 |
| `OutlineCleanError` | `outlineCleanService` | 400 |
| `DeckStructureError` | `deckStore`（删页/插页） | 400 |
| `DesignSpecError` | `designSpec.readDesignSpec` | 400 |
| `LayoutStateError` | `layoutState`（停用状态） | 400 / 500（读不出来那条是 500） |
| `PptImageError` | `imageService` | 400 |
| `ExportError` | `exportService` | 400 |
| `DemoNotFoundError` | `demoDeck` | 404（**纯文本**，见 §10） |
| `QuotaExceededError` | 平台配额 | 429 |
| `DedicatedChannelError` | 专属渠道缺档位 | 503 |
| 其余 `Error` | 案例库解析、`deckShell` 拼装 | 500 |

**`error` 这个键名不能改。** 前端 `lib/api.ts` 只认 `{error: string}`（对外中转那条 `/api/v1/*` 是另一套 OpenAI 形状，不在 PPT 范围内）。

## 2. 归属与鉴权

| 场合 | 状态码 | 文案 |
| --- | --- | --- |
| 没有任何身份（既没登录也没有 pk 短 token） | 401 | `请先登录` |
| `/api/` 下 PROTECTED 无 token | 401 | `Authentication required` |
| token 坏了/过期 | 401 | `Invalid or expired token` |
| scoped token 越权（`ppt:embed` 打到白名单外的路径） | 403 | `This token is scoped to "<scope>" and cannot access <METHOD> <PATH>` |
| 查不到这份稿子 / 不是这个归属的 | **404** | `这份演示稿不存在（或不是你的）` |
| 查不到这条素材 | 404 | `这条素材不存在（或不是你的）` |
| 挑图时素材不在库里 | 404 | `素材库里没有这张图（或者不是你的）—— 刷新一下挑图那个抽屉再试。` |
| 挑的素材已删 | 400 | `这张素材找不到了（可能已经在素材库里删掉了）—— 刷新素材库再挑一张。` |

**"不存在"和"不是你的"必须合成同一句、同一个 404。** 分开的话（一个 404 一个 403）就是一个存在性探测接口：换 id 试一遍能数出别人有多少份稿子，而每一次都是一个正常响应。

## 3. 建稿 / 改稿的入参校验

上限一律**只拒不截**。截断的后果全都长一个样：他写在后面那几条一个字都不生效，而界面上是一份"完整"的东西。

| 场合 | 状态码 | 文案 |
| --- | --- | --- |
| 名字空 | 400 | `请填写演示稿名字（或先贴一份提纲，第一行会当名字）` |
| 名字空（改名） | 400 | `名字不能为空` |
| 名字超长 | 400 | `名字最多 ${MAX_TITLE_CHARS} 字` |
| 提纲超长（建稿） | 400 | `提纲最多 ${MAX_DECK_OUTLINE_CHARS} 字，当前 ${outline.length} 字。请自己删减后再提交（不会自动截断）` |
| 提纲超长（改稿） | 400 | `提纲最多 ${MAX_DECK_OUTLINE_CHARS} 字，当前 ${n} 字（不会自动截断）` |
| 整份要求超长 | 400 | `整份要求最多 ${MAX_PAGE_NOTES_CHARS} 字，当前 ${n} 字（截断的话你写在后面那几条不会生效，所以这里直接拒）` |
| 单页额外要求超长 | 400 | `这一页的额外要求有 ${notes.length} 字，上限 ${MAX_PAGE_NOTES_CHARS} 字（截断的话你写在后面那几条不会生效，所以这里直接拒）。` |
| 设计规范缺一项 | 400 | `设计规范里少了${label}，没存 —— 缺一项的话那一项会悄悄回到默认那套。` |

| 改稿没有可改字段 | 404 | `没保存上：这份演示稿不存在（或这次没有要改的字段）` |
| 设计规范存不上（非 `DesignSpecError`） | 500 | `设计规范没存上`（兜底文案） |

**认不出的配色/字体/疏密一律 400，不回落默认。** 回落的话界面上那个下拉写着他挑的那个、而整份是默认配色 —— 两处对不上而一处都不报错。

### 插页 / 删页（`DeckStructureError`，全部 400）

| 场合 | 文案 |
| --- | --- |
| 规划读不出来（删） | `这份稿子存着的规划读不出来（plan_json 坏了），这一页没删 —— 删一页要连着改规划，只改一边会让页码和规划错开一位。` |

| 还没规划（删） | `这份稿子还没有规划，没有页可以删。` |
| 还没规划（插） | `这份稿子还没有规划，插不了页 —— 先点「开始规划」，那一步会按提纲分页。` |
| 页码越界（删） | `第 ${page} 页不在这份稿子的规划里（规划只有 ${list.length} 页）。刷新一下看看规划是不是换过了。` |
| 插入位置越界 | `插入位置不对（第 ${after} 页之后），这份稿子现在一共 ${list.length} 页。刷新一下看看页数是不是变了。` |
| 只剩一页还要删 | `整份只剩这一页了，不能删 —— 删完之后这份稿子看起来和「还没规划过」一模一样（提纲还在）。要清空请点「重新规划」。` |
| 到页数上限 | `这份稿子已经 ${list.length} 页，到上限 ${MAX_PAGES} 页了 —— 再插的话规划、生成、导出那几处对页数的假设都不成立。要加内容请先删掉几页。` |
| 新页标题空 | `新这一页的标题是空的 —— 生成出来会是一页没有标题的幻灯片，看起来像版式本来就这样。` |
| 标题超长 | `标题有 ${title.length} 字，上限 ${MAX_PAGE_TITLE_CHARS} 字（版式里标题就那么大一块，再长会挤成一团或被裁掉）。` |
| 空白页带了要点 | `空白页不吃要点 —— 那几条不会出现在页面上（空白页不走 AI 生成，内容全靠你自己往画布上摆）。要按要点排的话插一页普通的。` |
| 空白页挑了版式 | `空白页不挑版式（它就是一张空画布）—— 要用案例库里那条版式的话插一页普通的。` |
| 一条要点都没有 | `新这一页一条要点都没有 —— 只给标题的话模型会自己编这一页的内容，出来那一页读着通顺但不是你的东西。至少写一条。` |
| 要点过多 | `这一页有 ${points.length} 条要点，上限 ${MAX_POINTS_PER_PAGE} 条。拆成两页更好排。` |
| 某条要点超长 | `第 ${i + 1} 条要点有 ${len} 字，上限 ${MAX_POINT_CHARS} 字 —— 一条要点是一行字，太长会被版式裁掉。` |
| 推不出版式 | `这一页没有版式（前后页也读不出来），插不进去 —— 没有版式的话生成那一步是「模型自己看着办」，出来一页和这份稿子不是一套设计。` |
| 版式认不出（插页端点先判） | `没有版式 ${picked} —— 案例库里只有 ${全部 id join ' / '}。` |

`blank` **只认布尔 `true`**，不认 `'false'` / `0` 这些真值不明的写法。认宽了的话前端某次漏传成字符串就会插进一页空白页，而界面上它是"已生成"的一页空幻灯片。

## 4. `plan_rev` 页序版本号（这两句最容易被简化坏）

按页码写库、而且要花时间的那几条路都要过这一关。生成一页要三十秒以上，这期间他删掉/移动一页的话，回来那份结果会 upsert 到**现在的**那个页码上。

**缺 `planRev` → 400：**

```
这次请求没带 planRev（页序版本号），没执行 —— 带上它才能确认你点的那一页和库里现在的第几页是同一页。刷新页面重试。
```

**不匹配 → 409：**

```
这份稿子的页数/页序在你打开之后变过（你这边是第 ${rev} 版，库里是第 ${deck.plan_rev} 版），这次没执行 —— 照做的话结果会落在现在的那个页码上，而那已经不是你点的那一页了（出来是一页正常的幻灯片，只是内容对不上标题）。刷新页面再试。
```

**两个版本号都要写出来。** 只说"请刷新"的话，它和网络错误在他眼里是同一句话。
**缺号必须 400，不能"没带就跳过校验"** —— 前端某次漏传之后这一整套并发保护静默失效，而现象只是"偶尔某一页内容对不上标题"。

`POST /plan`（重新规划）的响应里**必须回新的 `planRev`**：不回的话前端手里那个号立刻过期，规划完点第一次生成就是一句 409，而他刚刚才在这里成功规划过。

`services/ppt/pageService.ts` 里还有两句是**服务内部**的（不该出现在用户面前，但要照搬）：

## 6. `jsonFailMessage`：所有 JSON 解析失败共用的**同一份**实现

`outlineCleanService` / `planService`（规划、重排图位）/ `aiEditService` / `aiRemakeService` 五处全部调它，**不许各写一份** —— 改了一边另一边照旧，而两边是同一个模型的同一个毛病。

```
输入: what（这次干什么，中文短语）, raw, finish, reasoningTokens, budget, noThinkingRequested

burnedByThinking = reasoningTokens && reasoningTokens >= budget * 0.9
cot = reasoningTokens ? `，其中思维链占 ${reasoningTokens} token` : ''

why = raw 全是空白  → `模型没有返回内容（finish_reason=${finish || '未知'}${cot}）`
      finish==length → `模型返回被截断（finish_reason=length${cot}）`
      否则           → `模型没有按 JSON 格式返回`

ignored = noThinkingRequested && reasoningTokens > 0

how = ignored →
        `这次已经把「不使用深度思考」发给上游了，但它没照办（照样想了 ${reasoningTokens} token`
        + (burnedByThinking ? `，${budget} token 的额度基本全花在这上面，正文没写出来` : '')
        + `）——这个开关对这条接入点/这个模型无效，后台再勾一遍也没有用。`
        + `唯一管用的是去「专属 AI / 系统配置」把这一档换成一个本身不带思维链的模型`
        + `（模型名里带 thinking / reasoning / R1 的那些都会这样）`
      burnedByThinking →
        `这次 ${budget} token 的额度基本全花在思维链上了，正文没写出来。再点一次通常就好；`
        + `老是这样就去「专属 AI / 系统配置」换一个不带思维链的模型`
      否则 → `再试一次或换个模型`

return `${why}，${what}没生成。${how}（这次的 AI 额度已经扣了）`
```

三处不能动的边界：

1. **报错里必须带思维链 token 数。** 不带的话他只会一路调高 `max_tokens`，而那个数字永远调不完（思维链算进 `max_tokens` 却不出现在 `content` 里，同一个模型这个差额在 0 到 9700 之间乱跳 —— 所以症状是"有时"格式错误、"有时"空返回，完全指不到额度上）。
2. **`noThinkingRequested` 决定这句话往哪儿指。** 要求过关思维链而 `reasoningTokens` 仍大于 0 = 那四个键发出去了但上游既不报错也不照办。这时候"去把思维链关掉"是一条走不通的路：他已经勾上了、界面上写着"已关闭"，他只会反复回去核那个开关，而唯一的解法是换模型。不带这个标记的话两种成因合成同一句话。
3. **不写死是哪个档位**（default / strong / fast 都有调用方）。说错档位比不说更糟：他会去改一个跟这次调用无关的配置，然后发现还是这样。

`finish_reason=length` **不重试** —— 同样的 body 断在同一处，只是把 token 和时间花两遍。

各处的 `what`：`提纲整理` / `排版规划` / `第 ${page} 页重排图位` / `这一块的改动` / `这一块的改造`。
生成一页那条走的是同一个句式但自己拼：`${why}，这一页没生成。${how}（这次的 AI 额度已经扣了）`。

## 13. 验收清单

移植完之后按这几条核一遍（每一条都是"跑绿了但那条约定没生效"的入口）：

1. **逐字对。** 拿这一份和 Python 侧的文案做 diff，插值位置也要一样（`${page}` 在句首还是句中影响他能不能一眼看出是哪一页）。
2. **每一条 400 都要有一个测试或一次手测。** 400 是他看得见的（手测就够），所以**不写测试**；真正要写测试的是那几条"出错时会伪装成成功"的：`plan_rev` 409、`checkRegionGuards` 六道闸、AI 编辑动了文案、图表重算的 `notes` 有没有真的回出来。
3. **`notes` / `problems` / `chartNotes` / `warnings` 四个通道在前端都要有落点。** 后端回了前端不显示，接口和页面都完全正常 —— 这是这个模块最容易漏的一处。
4. **状态码不要合并。** 401/403/404/409/429/503 各自对应一种下一步动作，全回 400 的话前端分不出该刷新、该登录、还是该联系管理员。
5. **别把"部分成功"改成 200 静默。** 这一份里带"这次调用已经花掉了"的那几条全是部分成功，回 200 的话他会再点一次（再花一次钱）。
6. 那两处写死的 **22 条** 改成动态条数（§5 末尾那条注）。
