# 设计系统 · 设计令牌

> 这一份是**跨配色通用**的部分：角色变量的语义、字号阶梯、间距、组件类。
> 每份稿子实际用哪套配色/字体/疏密，由它自己的设计规范决定（`services/ppt/designSpec.ts`，
> 拼装时覆盖 `:root`）—— 所以这里**不写具体色值、不写具体字族、不写页面内边距**。

## 令牌变量（角色语义，注入 :root）
模板与组件类统一引用以下角色变量，不写死具体色值，因此任意调色板都能套：
```
--c-brand        主色（最大面积强调：角标、标题强调、渐变起点、编号徽章）
--c-brand-deep   主色深版（渐变末端点、hover、下划线）
--c-accent       点缀色（第二色：kicker、次强调、渐变终点）
--c-accent-deep  点缀色深版
--c-brand-on     **压在品牌色实底上的字色**（徽章、圆按钮、通栏色块、品牌色页眉）
--c-accent-on    压在点缀色实底上的字色
--c-bg           页面底色（浅）
--c-bg-alt       区块/卡片底（浅，可带微色相）
--c-ink          正文
--c-ink-deep     标题
--c-ink-soft     次要/水印
--c-card         卡片底
--c-hairline     描边
--mask-rgb       全幅背景遮罩用的底色 RGB（= --c-bg 的 rgb，透明度梯度由 CSS 控制）
--mask-rgb-alt    cool 页遮罩底色 RGB（= --bg-cool 的 rgb，也就是 .slide.cool 那一档真正的底色）
```

**硬约束**：所有底色明度 ≥ `#EBF6FC`（浅色无暗黑）；正文/标题对比度达标（AA）。

**色块上的字一律写 `var(--c-brand-on)` / `var(--c-accent-on)`，不许写 `#fff`。**
这两个变量**不是白色的别名**：白字只在深底上成立，而品牌色深浅由这份稿子的配色决定 ——
默认那套的橙对白字只有 2.6:1、天青 2.3:1（AA 要 4.5），所以那两档压的是墨色。写死白的那一处
换成浅色品牌色时字直接读不出来，而浏览器、`checkPage`、导出全都正常，现象只是「这一页字有点看不清」。
反过来，**全幅照片上的白字照旧写白色**（`.l60-pills` / `.l55-sign` 那几处压的是深色蒙版，不是色块）。

## 调色板 / 字体 / 疏密的实际取值
这三样是**每份稿子自己选的**（配色 / 字体 / 疏密三档，见 `services/ppt/designSpec.ts`），
由拼装时覆盖 `:root` 生效，本文件**不再列具体色值**。

> 这里以前列着五套配色的具体色值和一套「按行业推导配色」的规则，已经删掉：那些 id 被代码里
> 那份占了（同一个 id 在两边是两套颜色），而这一整段是**原样发给模型的** —— 它会照表把色值
> 写死在 inline style 里，那一页看起来完全正常，只是换配色那天它一个人不跟着变。
> 要加一套配色就加在 `designSpec.ts` 的 `PALETTES` 里（有测试盯着「20 个角色变量给齐了没有」）。

## 字体
- 标题/企业名/金句用 `var(--serif)`，正文/UI 用 `var(--sans)`。
- **不要写 font-family**：这两个变量的实际字族由这份稿子的规范决定（默认宋体标题 + 黑体正文，
  也可能是全黑体/全宋体）。写死的那一处换字体时不跟着变，而它读起来完全正常。
- 禁止系统字体（Arial/Inter/Roboto）与白底紫渐变滥用方案。

## 字号阶梯（1920×1080 舞台）
- 页标题 54px / 章节封面 72px / 企业名 72px
- 金句 38–44px / 正文 22–24px / kicker 20px / 水印 20px
- 编号徽章 112×112，内部数字 48px
- **最小 14px，没有例外**（说明文字、单位、英文标记、tag、表格里的口径都算）。这张舞台投到
  1080p 是 1:1，13px 在会议室后排读不出来 —— 而它在电脑上看着完全正常，一处都不报错。
- **内容塞不下时不许压字号**：删一句、拆成两页、或者换一条容量更大的版式。压字号是唯一一种
  「看起来解决了」的做法（每个字都在、排得满满当当），也是唯一一种投出来才发现的做法。

### 巨标题按字数降级（案例里那个字号不是常量）
案例里写的 `78px` / `96px` / `116px` 是**那句话那个长度**下的取值。这张舞台一行可用宽度约
1600px（页边距按疏密档在 108–176px 之间），中文一个字约等于一个字号宽 —— 所以标题一长，
照抄案例的字号就会折成三行、行高 1.05 的大字顶到下面的装饰条或图上，或者被 `.slide` 的
`overflow:hidden` 切掉最后一行。**页面照样渲染**，看起来像「这一页设计得很满」。
按字数选一档（中文字数，满宽容器）：

| 中文字数 | 字号 | 行数 |
| --- | --- | --- |
| 2–6 字 | 96–116px | 1 行（只占 40–55% 宽，右边那片留白是设计的一部分，不要拿别的东西填） |
| 7–10 字 | 78–96px | 1 行 |
| 11–14 字 | 64–78px | 1 行满宽，或 2 行 |
| 15–20 字 | 54–64px | 2 行（这时它已经是普通页标题那一档，别再当巨标题排） |
| 20 字以上 | **不要用巨标题版式** | 那不是标题是一句话：拆成「短标题 + 副标题」，或者换金句页（38–44px） |

- **半宽容器里字数上限折半**：巨标题只占 60% 宽的版式（分屏、带装饰列的那几条），10 个字就该退到 64px。
- 降级**只准改字号**：压行高到 0.9 以下、把字距改成负数、把它降到小字档，这三条都是
  「看起来解决了」——投出来是一坨挤在一起的大字，而生成那一刻没有一处会说。
- 英文/数字巨标题（`.l58-echo` 172px、`.big-num` 150px 那种）按**字符宽**算，规则同上：
  英文全大写一个字符约 0.6 个字号宽。

### 字号 ↔ 字重（越小越要粗）
投影仪的对比度比显示器低一档，**细笔画在屏幕上直接消失**，而它在电脑上完全正常：

- ≥72px：中文用 **700**（衬线标题就是 700）。800/900 只留给 `var(--num)` 的数字和英文全大写 ——
  中文大字上 900 会把笔画糊成一团，投出来比 700 还难读。
- 54–64px（页标题）：700。
- 38–44px（金句）：600–700。
- 22–24px（正文）：400，行高 1.7–1.8。
- 14–20px（kicker、单位、口径、英文标记、表头）：**600–800，并且加宽字距 0.04–0.3em** ——
  这一档用 400 在投屏上是一片灰。库里所有 kicker 都是 600–800，照它写。
- **54px 以下不许用 300 及以下的字重**（`.l13-year` 那个 `font-weight:200` 是 96px 的年份装饰，
  不是内容）。细体小字是这套库最容易出的一处：它在设计稿截图里很高级，投到会议室就没有了。
- 小字**不许再靠 `opacity` / rgba 透明度打折**：14–17px 的字压到 `opacity:.6` 之后有效对比度
  比 12px 的实心字还低，而两者在电脑上看着都清楚。要弱化就换 `var(--c-ink-soft)`。

## 间距与圆角
- **页面内边距不要自己写**：`.slide-inner` 的 padding 由这份稿子的疏密档决定（舒展/标准/紧凑三档）。
  写死的那一页在换档之后和别的页对不齐，而两页各自都正常。标题下装饰条 90×6（主色→点缀渐变）
- 卡片圆角 12–14px；图圆角 12px；边框 1px hairline
- 顶部 5px 渐变色带（主色→点缀）
