# 布局模式库（案例库）

> 活文档：每完成一个满意版式，追加一条。设计阶段按"适用内容类型"匹配，而非凭空想。
> 全局约束：浅色无暗黑、每页唯一视觉主角、相邻页版式去重（连续≤2页同版式）。
>
> **★ 核心原则：案例只关注排版结构，颜色和内容不固定**
> - **结构是灵魂**：网格分区、视觉层级、空间关系、构图手法才是要学的东西。
> - **颜色不绑死**：所有配色必须用 `var(--c-brand)` 等变量，同一版式在橙/蓝/黄/双色系 deck 里都能成立。案例里的配色归一表只做"原色→变量映射"，不指定具体色值。
> - **内容不绑死**：版式名按**结构手法**命名（如 `circle-float-card` 而非 `bio-portrait-card`），"适用内容类型"应列出多种场景（人物介绍/产品介绍/项目展示…），圆形视觉主体可以是头像、产品图、logo、图标——任何圆形 crop 的视觉元素。
>
> **📄 详情标记**：带「📄 详情」的条目，design 阶段匹配到时**必须读 `cases/L<编号>-<名>.md`** 获取完整 CSS 骨架、build-part 结构模板、图槽位与变体说明。无此标记的条目信息在本文件内已自足。
>
> **★ 页型分类（`归属` + `形状`）**：每条都有这两行，是**代码解析的**（`layoutLibrary.ts`；词表外的字、或者哪一条漏了这两行，直接抛错）。
> - `归属` = 这一条能当**什么页**用，可多选：`封面`（整份第 1 页）/ `目录` / `章节`（章节扉页、过渡页）/ `内容` / `结尾`（总结、收尾金句）。
> - `形状` = 内容的**骨架形状**，单选：`聚焦`（单一主角：金句 / 人物 / 产品 / 整页一句大标题）/ `分屏`（左右或上下两段，图文各占一半）/ `并列`（3–4 个同构单元横排）/ `对比`（两块对立）/ `数据`（大数字、指标）/ `时序`（时间轴、阶段推进）。
> 规划那一步按 `归属` 把清单分组发给模型，并核对它给每页标的页型（`kind`）和挑的版式对不对得上。
> **归属少写一个词的表现是「这一条从此不出现在某个分组里」**：清单看着还是 44 条，只是封面页再也挑不到它，
> 而规划出来的每一页都合法、一处都不报错。

## L1 · hero-right-visual（右侧全高视觉） 📄 详情
