# HTML 展示稿（/ppt）

> 平台级约定（协作方式 / 三条硬规则 / 架构与约定 / AI 网关与配额 / 对外中转接口 / 环境变量）
> 在 `CLAUDE.md`，这里只记本模块的坑，不重复。

- **22 个 L 版式案例的唯一来源是仓库里的 md（`server/src/services/ppt/library/`），不是库、也不是
  `~/.workbuddy/skills/`。** 原来那套在作者机器的 skill 目录下，线上没有那个目录 —— 而读不到案例
  不报错：生成阶段拿不到任何排版参考，照样出一份完整的 HTML，只是版式全靠模型编。本机好使、线上
  悄悄变差，唯一症状是「质量不行」。所以文件跟着代码走，且解析出 **0 条必须抛错**（返回空列表的话
  下游会照空列表继续生成）。参考截图放 `client/public/ppt-cases/`（跟着前端构建走），图 404 要写出来
  （现在写在抽屉里那张原图上方）—— 破图图标和「这条本来就没有参考图」长得一样，而前者说明那个目录
  没跟着部署上去。
- **每条案例拆成 `selectText`（短）和 `buildText`（长，详情 md 全文）两份文本，喂给两次不同的调用。**
  选版式那次 22 条一起进 prompt，混上 12 份 CSS 骨架（近 2000 行）会把客户内容挤到上下文末尾，模型
  开始凭空挑版式 —— 而挑出来的那个版式名读起来完全正常。生成某一页时只带**那一条**的 buildText。
- **详情 md 按 `L<编号>-` 前缀找，不按版式名。** L12 的文件名还是 `L12-bio-portrait-card.md`，而条目名
  早按结构改成了 `circle-float-card`（案例只关注结构，名字跟着结构走）。按名字找那条会被判成「无详情」，
  生成时拿不到 CSS 骨架，页面结构自由发挥，而列表上看不出区别。
- **`fullbleed` 两个来源：条目里的「是否全幅」优先，没写的按文末那句「★ 全幅版式集合（L2 / L3 / …）」判。**
  L2/L3 那几条老条目压根没有这一行，只认字段的话它们会被包进 `.slide-inner`，出来是一张四边留白的
  「全幅」图，不报错。L12 明写「否」但要 `has-card`（色带得溢出卡片边缘）。
- **22 个版式的效果 demo 是「一份 deck 请求时拼出来的」，不是 22 个独立 html**
  （`demoDeck.ts` = `library/template.html` + `library/demo-slides.html` 的 `<section>` 片段，
  片段靠 `<!-- @demo L<编号> -->` 那行切分）。各存一份完整 html 的话，改了 template 里某个版式的
  CSS 之后 demo 照旧好看、生成出来的页面已经变了 —— 而案例库的全部作用就是「照我们的骨架跑出来长
  这样」，漂开的那一刻这个页面就在骗人，两边都不报错（`client/public/ppt-cases/L1x-demo.html` 那三份
  抄来的独立 demo 因此不再被引用）。所以**片段里一行 CSS 都不许写**，只准用 template 里已有的类名
  （`demoDeck.test.ts` 逐个 token 核 —— 类名拼错不报错，那一块只是回到默认流式布局，看起来是版式
  本身塌了），临时调整用 inline style；图统一用 `/ppt-cases/ph-*.svg` 占位（配真照片会让人按那张
  照片的调性去期待产出）。卡片缩略图放 demo 而不是原始截图，截图降级到抽屉里标「原图参考」：那是
  别人家 deck 的截图，用户照它期待颜色，拿到自己品牌色的那一版会以为生成质量不行。
- **demo 那条路径（`GET /api/ppt/demo-deck.html`，`?only=Lk` 只出一页）有三个「一块白但接口 200」的坑**：
  它必须在 `ROUTE_AUTH_CONFIG` 里登记成 **public**（`<iframe src>` 带不了 Authorization 头，而 `/api/`
  默认 protected，于是每张卡里显示的是一句 `Authentication required`）；`app.ts` 那句全局
  `X-Frame-Options: DENY` **连同源 iframe 一起拦**，所以这条路径单独发 `SAMEORIGIN` +
  `frame-ancestors 'self'`；`/api/ppt` 的限额给到 300/分钟（案例库一页就是 22 个 iframe，60 的话翻两页
  就被 429 挡住，而卡片上照样挂着「效果 demo」）。找不到片段时回 404 **纯文本原文**而不是空 deck ——
  空 deck 在 iframe 里是一块白加一个「1 / 1」页脚，读起来像那个版式渲染塌了；`{"error":…}` 在 iframe
  里就是一行花括号。iframe 里**不要**再叠 `transform: scale()`：deck 自己的 `fit()` 已按 iframe 视口缩放，
  缩两遍就是贴在左上角的一小块；缩略图那个 iframe 要 `pointer-events:none`（deck 在 document 上挂了
  「点一下翻页」，不掐掉的话点卡片打不开抽屉，页面毫无反应）。
- **挑版式是「整份一次调用」（`planService.ts`，`POST /api/ppt/plan`），不逐页问。** 相邻页去重
  （连续 ≤2 页同版式）、封面/章节页走全幅、整份的节奏全是**跨页**约束；逐页问的话模型看不到上一页
  选了什么，出来的是「每页单看都合理、整份翻下来极其单调」的 deck —— 那种 deck 每一页都挑不出错，
  用户只会觉得「没什么设计感」，无从下手。**页码由代码按数组顺序给**（硬规则 3），prompt 里明写
  「不要输出页码」。这一步只挑版式不写 HTML，所以它的产出必须逐页显示**理由 + 那个版式的 demo**：
  「挑得准不准」只能靠这两样核，少了理由那一页就只剩一个版式名。
- **模型给的 `layoutId` 不在 22 条里就丢掉那一页并点名说出它给了什么，绝不静默替换成某一条。**
  `L23` / `hero-split` 读起来和真的一模一样，替成 L1 之后那一页排出来也好看 —— 只是不是模型挑的
  那个，而用户以为是。三处配套都要有声：截断时救回断点前那几页（`parseJsonArrayItems`，**只在**
  `finish==='length'` 时）并说「只规划到第 N 页」（不说的话界面上是一份「完整」的两页规划，而他
  的提纲有二十页）；连续 ≥3 页同版式**只报不改**（自动打散的话他以为是模型挑的，下次同样的提纲
  又是这个结果，永远不知道该改提纲还是改 prompt）；拿不到 JSON / 全部页都用了库里没有的版式一律
  抛错，不回 `{pages:[]}`（空规划在界面上和「这份提纲拆不出页」分不开）。提纲和页数上限**只拒不截**。
- **生成 HTML 是「一页一次调用」（`pageService.ts`，`POST /api/ppt/pages`），只带那一条版式的
  `buildText`。** 单条骨架近 8000 字，22 条一起带的话客户内容被挤到上下文末尾，出来照样是一份完整的
  HTML，只是内容开始跑偏 —— 没有一处会喊。跨页的事已经在 plan 那一次调用里定完了。
- **deck 外壳只有 `deckShell.ts:assembleDeck` 一份，22 个版式的 demo 和产出预览共用它**（预览的
  `previewHtml` 由**服务端**拼，不让前端拼一遍）。各拼一份的话「预览里好看、真 deck 里换了骨架」两边都
  不报错，而案例库的全部作用就是「照我们的骨架跑出来长这样」。类名白名单 `templateClasses()` **只扫
  `<style>` 里的选择器**：整个文件一起扫的话末尾那段 JS 里的 `document.querySelectorAll` 也算成类名，
  校验变成筛子，而筛子的表现就是「校验通过、页面塌了」（`demoDeck.test.ts` 用的是同一把尺子，它原来写
  `template.includes('.'+tok)` —— `.tr` 会因为 `.tri-col` 里含这两个字符而通过）。
- **一页里所有「渲染出来了但不对」的情况一律只报不改**（`checkPage`）：类名不在 template 里（那一块掉回
  默认流式布局，看起来是版式塌了）、自己写了 `<style>`（盖掉共享骨架、改的是整份 deck）或 `<script>`
  （真的会执行）、全幅版式包进了 `.slide-inner`（出来是一张四边留白的「全幅」图）、缺 `has-card`、
  规划要图而一张都没有、图片地址不是占位图（预览里是破图，而破图和「这一格本来是空的」长得一样）。
  只有**页码**是代码改的（硬规则 3：模型写的 `07 / 9` 看起来完全正常，只是和它在 deck 里的位置对不上），
  所以 prompt 里让它写 `{{PAGE}}`/`{{TOTAL}}`。拿不到 `<section>` **抛错**而不是回一段空 HTML（iframe
  里一块白读起来像这个版式渲染塌了），三种成因（空返回 / 截断在 `<section>` 之前 / 压根没按格式回）分开
  说且带思维链 token 数；缺 `</section>` 的补上闭合**并喊截断** —— 浏览器容错会照样渲染，下半页没了和
  「这一版设计得比较空」在屏幕上分不开。生图还没接，图槽位只能用 `/ppt-cases/ph-*.svg`，每个图元素带
  `data-img-prompt`（那是下一步生图的输入）。
- **配图是生成 HTML 之后独立的一步（`imageService.ts`，`POST /api/ppt/images`），入口只认
  `data-img-prompt`。** 生成阶段图槽位一律是 `/ppt-cases/ph-*.svg` 占位图 —— 占位图明显是「还没配图」，
  而模型编的地址或者一个坏地址在屏幕上和「这一格本来是空的」长得一样（所以失败的那几格**保留占位图**，
  绝不写回坏地址）。少了那个属性的图元素永远配不上图，`checkPage` 因此比对图元素数和属性数并喊出来。
  五条配套：**整页只解析一次接入点并 `providerId` 绑死它** + 整页只解析一次画风并按 id 绑死（按 kind 解析
  会挑「最近更新的那条」，于是一页里的图出自两个模型 —— 每张单看都不错，翻下来笔触不统一，而没有一处
  报错）；**比例只写进提示词，不发 API 的 `size`**（各家认的枚举完全不同，传一个
  「看起来对」的值会让整批图在某些接入点上全被拒，现象是「生图全失败」，而槽位本来是 `object-fit: cover`
  裁的）；**额度按张扣**（`checkAndDeductAppQuota('ppt')` + 非专属渠道再扣总额，顺序同 `aiGateway`），
  撞墙时**不回滚已经生成的那几张**（钱花了，抛掉整个结果等于让他再花一遍）并停在那里；**每张成功的图
  写一条 `ai_logs`**（`operation='gen-image'`，`imageGateway` 自己不写日志 —— 不补的话生图这笔钱在后台
  一处都看不见）；**`storage='local'` 必须出声**（COS 没配好时图落在本机磁盘，换机器/多实例之后那几张
  是 404，而生成那一刻预览里一切正常）。已经不是占位图的槽位**默认跳过**（重做一次是一次真实花费），
  「换一批图」才带 `force`。
- **画风（S-A ~ S-F）按 deck 选，唯一来源是 `library/illustration-style.md`（`styleLibrary.ts` 解析），不在
  代码里写死一份。** 写死那份的后果是 md 里改了/加了一套画风之后界面和图都照旧，读起来像「这个平台就这几种
  风格」；解析出 **0 套必须抛错**（回空列表的话下拉是空的、生图那一步回落成没有画风的裸提示词，出来的图每张
  单看都不错，只是和 deck 不是一套东西）。六条配套：**认不出的 styleId 一律抛错，绝不回落成默认那套** ——
  选了「国风水墨」拿到等距 SaaS 插画时没有一处报错，用户只会以为这个模型画不了水墨；**每套三路模板
  （concept / case / data）缺一路整条丢掉**，槽位用哪一路由生成阶段写的 `data-img-mode` 决定（填错的话
  数据页拿到一张漂亮的概念插画）；**`{{BRAND}}/{{ACCENT}}/{{BG}}/{{BG_ALT}}` 从 `template.html` 的 `:root`
  取真色值**，缺一个抛错 —— 图和 deck 不是一套色是唯一症状，而每张图单看都好；渲染完要核一遍
  **没有剩下的占位符**（`leftoverPlaceholders`，剩下的话「本页主题，1句」这几个字会原样发给模型）；
  画风和 mode 写进 `ai_logs` 的 operation 备注（事后追「这批图为什么笔触不统一」只能靠它）；
  **换画风不会自动重做已经配好的图**（那是一次真实花费），所以界面上每页要显示它用的是哪套画风，和当前
  选中的不一致时喊一句「点「换一批图」才会重做」—— 不喊的话整份 deck 里两套笔触混着，而没有一处报错。
- **前端配好图必须用返回的 `html` 覆盖那一页存着的 html，并作废拼好的整份。** 不覆盖的话拼整份用的还是
  占位图那一版，而预览里刚刚明明看到图了。反过来「重新生成这一页 HTML」会把图换回占位图，所以已经配过图
  的那一页要先确认一次 —— 不问的话那一页在预览里只是「这版设计得比较空」。
- **拼整份走 `POST /api/ppt/deck`（`buildDeck`，不调 AI），缺一页就 400 并点名缺哪几页。** 缺页的 deck
  翻起来和完整的一模一样，只是内容跳了一段，而页脚那个「/ 12」是按**规划总页数**由代码写的，连页码都看不
  出缺口。顺序**只按 `page` 排**，不按前端传来的数组顺序（批量是逐页回来的，传进来可能是完成顺序 ——
  照它拼出来每一页都对、章节全乱）。**任何一页重新生成、或者重新规划，都要把拼好的那份作废**：留着的话
  它翻起来完全正常，只是那一页还是改之前的版本。
- **批量生成在前端串行跑，逐页一次真实调用**（`PptPlan.vue:runAll`，只补还没生成的那几页）。并发一批会撞
  上游频控，而回来的错误读起来像模型不行；额度打满要**立刻停**（接着跑十几页只会拿到十几条一样的错误，
  中间还夹着刚才那几页的成功）；收尾那句话逐类报数（成功 N / 失败哪几页 / 额度 / 你点了停止还剩几页），
  合成一句「已完成」的话失败的那几页在界面上就是「还没生成」的样子。**必须有「停止」**：不给停就是把剩下
  十几次额度花完；它只置位、当前那一页跑完再停（掐断的话那次的额度已经花了，而界面上是「没生成」）。
  批量期间禁掉「重新规划」—— 换一份规划会清掉已生成的页，而那一刻还有一页在跑，它回来时会挂到新规划的
  同一个页码下面，版式和内容都不是那一页的，两边都不报错。
- **前端「重新规划」必须清掉已生成的那几页**（`PptPlan.vue`）：新规划的第 3 页很可能换了版式和内容，而旧
  的那一版会照旧挂在「第 3 页」下面，两边都不报错。单页生成失败的错误要显示**在那一页上**且保留上一版
  —— 顶上一条全局错误看不出是哪一页，而清掉上一版会让「重新生成失败」和「还没生成过」长得一样。
- **导出 .html（`POST /api/ppt/export`，`exportService.ts`）走同一个 `buildDeck`，并且必须把图的相对地址
  改成绝对地址。** 生成出来的图是 `/ppt-cases/ph-*.svg` / `/uploads/x.png`，存成文件后 `file://` 下这两个
  路径指向磁盘根目录 —— 整份 deck 的图**全是破图**，而文字、版式、翻页全正常，看起来像「这份稿子设计上
  就没配图」。`baseUrl` 由前端传 `location.origin`：服务端按 `req.protocol` 算的话反代后面拿到的是 http，
  混合内容被浏览器拦掉，那几格照样只是「没配图」。**回 JSON（前端自己 Blob 下载）而不是 attachment**，
  因为这份文件依赖什么必须显示在界面上：还剩几格占位图、几张图落在 `/uploads`（换机器就 404）、字体走
  Google Fonts（取不到就掉回系统字体，字重字距变了像版面塌了）、导出地址是 localhost（发给别人打不开）
  —— 这四样在导出那一刻的预览里全看不出来，用户是转给同事打开时才发现，而那时没有一处能说明成因。
  文件名要洗掉路径分隔符（`a/b.html` 会让浏览器存到别处或直接不下载，那次点击什么都不发生 = 读起来像
  功能坏了），下载那几行的失败也要走错误横幅。**任何一页改过之后「已导出」那句话要改口**（`invalidateDeck`）：
  留着的话他以为手上那个文件是最新的。图和字体还没打进文件里（真单文件是后面的一片），所以话术里
  「要能访问到平台」这半句是硬的。
- **一份稿子落库（089 `ppt_decks` / `ppt_deck_pages`，`services/ppt/deckStore.ts`），入口是 `/ppt/decks`
  列表 → `/ppt/decks/:id` 工作台**（同 consult 的项目列表）。不落库的话一份 12 页的 deck 是十几次真实
  调用，刷新/关页面全没了而界面上一句错都没有。四条：**`deckShell` 的派生物一律不存**（previewHtml /
  拼好的整份 / demo）—— 存下来的话改了骨架之后旧 deck 用旧骨架渲染、导出用新的，两边都不报错；
  **`updateDeckMeta` 只改 `!== undefined` 的列**（缺省成空串的话任何一次只改名字的保存都清空提纲，
  而两边都回「已保存」）；**名字缺省取提纲第一行但存下来、不每次现算**（现算的话改一次提纲第一行，
  列表里那份稿子就换了名字，读起来像另一份）；**一个字段都没传的 PATCH 回 404 而不是 200**，
  否则前端那句「已保存」是假的。所有查询都带 `user_id`（少了它，另一个账号的 deck id 读/改到的是他的
  稿子，而响应完全正常）。
- **前端那句「哪些东西存下来了」是承重的**（`PptPlan.vue` 的 `.save-note`）：规划结果和逐页 HTML/配图
  这一版**还没**落库，不写出来的话他会以为都存着，关掉页面回来只剩提纲，而那十几次调用的额度已经花了。
  保存失败一律显示原文（静默失败 = 他改完提纲走了，下次回来是上一版，中间界面上什么都没说），
