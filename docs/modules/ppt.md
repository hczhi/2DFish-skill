# HTML 展示稿（/ppt）

> 平台级约定（协作方式 / 三条硬规则 / 架构与约定 / AI 网关与配额 / 对外中转接口 / 环境变量）
> 在 `CLAUDE.md`，这里只记本模块的坑，不重复。

- **22 个 L 版式案例的唯一来源是仓库里的 md（`server/src/services/ppt/library/`），不是库、也不是
  `~/.workbuddy/skills/`。** 原来那套在作者机器的 skill 目录下，线上没有那个目录 —— 而读不到案例
  不报错：生成阶段拿不到任何排版参考，照样出一份完整的 HTML，只是版式全靠模型编。本机好使、线上
  悄悄变差，唯一症状是「质量不行」。所以文件跟着代码走，且解析出 **0 条必须抛错**（返回空列表的话
  下游会照空列表继续生成）。参考截图放 `client/public/ppt-cases/`（跟着前端构建走），图 404 要写出来
  （现在写在抽屉里那张原图上方）—— 破图图标和「这条本来就没有参考图」长得一样，而前者说明那个目录
  没跟着部署上去。
- **每条案例拆成 `selectText`（短）和 `buildText`（长，详情 md 全文）两份文本，喂给两次不同的调用。**
  选版式那次 22 条一起进 prompt，混上 12 份 CSS 骨架（近 2000 行）会把客户内容挤到上下文末尾，模型
  开始凭空挑版式 —— 而挑出来的那个版式名读起来完全正常。生成某一页时只带**那一条**的 buildText。
- **详情 md 按 `L<编号>-` 前缀找，不按版式名。** L12 的文件名还是 `L12-bio-portrait-card.md`，而条目名
  早按结构改成了 `circle-float-card`（案例只关注结构，名字跟着结构走）。按名字找那条会被判成「无详情」，
  生成时拿不到 CSS 骨架，页面结构自由发挥，而列表上看不出区别。
- **`fullbleed` 两个来源：条目里的「是否全幅」优先，没写的按文末那句「★ 全幅版式集合（L2 / L3 / …）」判。**
  L2/L3 那几条老条目压根没有这一行，只认字段的话它们会被包进 `.slide-inner`，出来是一张四边留白的
  「全幅」图，不报错。L12 明写「否」但要 `has-card`（色带得溢出卡片边缘）。
- **22 个版式的效果 demo 是「一份 deck 请求时拼出来的」，不是 22 个独立 html**
  （`demoDeck.ts` = `library/template.html` + `library/demo-slides.html` 的 `<section>` 片段，
  片段靠 `<!-- @demo L<编号> -->` 那行切分）。各存一份完整 html 的话，改了 template 里某个版式的
  CSS 之后 demo 照旧好看、生成出来的页面已经变了 —— 而案例库的全部作用就是「照我们的骨架跑出来长
  这样」，漂开的那一刻这个页面就在骗人，两边都不报错（`client/public/ppt-cases/L1x-demo.html` 那三份
  抄来的独立 demo 因此不再被引用）。所以**片段里一行 CSS 都不许写**，只准用 template 里已有的类名
  （`demoDeck.test.ts` 逐个 token 核 —— 类名拼错不报错，那一块只是回到默认流式布局，看起来是版式
  本身塌了），临时调整用 inline style；图统一用 `/ppt-cases/ph-*.svg` 占位（配真照片会让人按那张
  照片的调性去期待产出）。卡片缩略图放 demo 而不是原始截图，截图降级到抽屉里标「原图参考」：那是
  别人家 deck 的截图，用户照它期待颜色，拿到自己品牌色的那一版会以为生成质量不行。
- **demo 那条路径（`GET /api/ppt/demo-deck.html`，`?only=Lk` 只出一页）有三个「一块白但接口 200」的坑**：
  它必须在 `ROUTE_AUTH_CONFIG` 里登记成 **public**（`<iframe src>` 带不了 Authorization 头，而 `/api/`
  默认 protected，于是每张卡里显示的是一句 `Authentication required`）；`app.ts` 那句全局
  `X-Frame-Options: DENY` **连同源 iframe 一起拦**，所以这条路径单独发 `SAMEORIGIN` +
  `frame-ancestors 'self'`；`/api/ppt` 的限额给到 300/分钟（案例库一页就是 22 个 iframe，60 的话翻两页
  就被 429 挡住，而卡片上照样挂着「效果 demo」）。找不到片段时回 404 **纯文本原文**而不是空 deck ——
  空 deck 在 iframe 里是一块白加一个「1 / 1」页脚，读起来像那个版式渲染塌了；`{"error":…}` 在 iframe
  里就是一行花括号。iframe 里**不要**再叠 `transform: scale()`：deck 自己的 `fit()` 已按 iframe 视口缩放，
  缩两遍就是贴在左上角的一小块；缩略图那个 iframe 要 `pointer-events:none`（deck 在 document 上挂了
  「点一下翻页」，不掐掉的话点卡片打不开抽屉，页面毫无反应）。
- **挑版式是「整份一次调用」（`planService.ts`，`POST /api/ppt/decks/:id/plan`），不逐页问。** 相邻页去重
  （连续 ≤2 页同版式）、封面/章节页走全幅、整份的节奏全是**跨页**约束；逐页问的话模型看不到上一页
  选了什么，出来的是「每页单看都合理、整份翻下来极其单调」的 deck —— 那种 deck 每一页都挑不出错，
  用户只会觉得「没什么设计感」，无从下手。**页码由代码按数组顺序给**（硬规则 3），prompt 里明写
  「不要输出页码」。这一步只挑版式不写 HTML，所以它的产出必须逐页显示**理由 + 那个版式的 demo**：
  「挑得准不准」只能靠这两样核，少了理由那一页就只剩一个版式名。
- **模型给的 `layoutId` 不在 22 条里就丢掉那一页并点名说出它给了什么，绝不静默替换成某一条。**
  `L23` / `hero-split` 读起来和真的一模一样，替成 L1 之后那一页排出来也好看 —— 只是不是模型挑的
  那个，而用户以为是。三处配套都要有声：截断时救回断点前那几页（`parseJsonArrayItems`，**只在**
  `finish==='length'` 时）并说「只规划到第 N 页」（不说的话界面上是一份「完整」的两页规划，而他
  的提纲有二十页）；连续 ≥3 页同版式**只报不改**（自动打散的话他以为是模型挑的，下次同样的提纲
  又是这个结果，永远不知道该改提纲还是改 prompt）；拿不到 JSON / 全部页都用了库里没有的版式一律
  抛错，不回 `{pages:[]}`（空规划在界面上和「这份提纲拆不出页」分不开）。提纲和页数上限**只拒不截**。
- **规划顺手给每页 2-3 条备选版式（`PlannedPage.alts`），生成前那个对话框把它们和规划挑的那条
  排在下拉最前面。** 22 条平铺的话「换一个也装得下这一页的版式」等于从 22 条里自己认 —— 他要么
  不换，要么挑一条装不下的，而出来照样是一页完整的幻灯片（内容挤成一团，没有一处会说）。四条
  是承重的：**代码校验**（不在库里的丢掉、和 `layoutId` 重复的丢掉、最多 3 条）——编出来的编号留
  在下拉里的话他挑中之后是一句 400，读起来像「这个版式坏了」，而重复的那条会让最前面那组出现两个
  「规划挑的」，看起来像只给了一条备选；**丢掉了要汇总说一句**（静默的话那一页下拉最前面只剩一条，
  和「模型认为只有这个版式合适」分不开），报错里放**模型原样给的那个串**而不是大写过的（调 prompt 时
  有用的只有它到底写了什么）；整份汇总成一条、不逐页刷（40 页会把真正要看的那几条 problems 冲下去）；
  **老 deck 的 `plan_json` 里没有这个字段**，那时对话框里要写「重新规划一次才有备选」——不写的话
  上面那组只有一条，同样读成「只有这个版式合适」。备选**不缩小可选范围**（其余的照旧列在下面）：
  只给备选的话他想用的那条压根挑不到，而下拉看起来是完整的。
- **「这一页画哪几张图」在规划那一步就定下来（`PlannedPage.imageSpecs`：subject + mode + ratio，
  枚举和一页上限的唯一定义处是 `imageSpec.ts`）。** 原来只给一个张数，于是配图唯一的输入是
  **生成 HTML 那一次写出来的** `data-img-prompt` —— 也就是必须先出 HTML 才知道要画什么，
  页面第一次显示出来必然是缺图的占位版，而「重新生成这一页」会连配图记录一起清掉、图钱要再花一遍。
  `images`（张数）**按 `imageSpecs.length` 算**，不用模型给的那个数字：两个数各自存的话面板上写着
  「要 2 张」而下面列着 3 条规格，两处都读起来正常。四处归一都要出声：mode 不在
  `concept/case/data` 里（数据页会拿到一张漂亮的概念插画）、ratio 不在 `16:9/1:1/3:4` 里
  （占位图只有这三种，`ratioOf` 按文件名认比例 —— 写第四种的话那一格仍按 16:9 生图而规划面板上写着 3:4）、
  subject 空着（生不出任何东西，那一格停在占位图上）、超过一页 6 张（备出来也没有槽位放 = 白花钱）。
  **模型只回了个数字**（老格式/偷懒）也要单独喊一句：那一页没法提前备图，会静默退回「先 HTML 后配图」
  的老顺序，而界面上只是又变成图位全是占位图，看起来像备图功能坏了。`imageSpec.ts` 单独成文件是因为
  `imageService` 拖着生图网关 + COS + 上传路由那一整串 import，规划那一步不该把它们拉进来。
  老 deck 的 `plan_json` 里没有这个字段（工作台那里显示「重新规划一次才会有逐张说明」）。
- **「先备图」是独立一步（`POST /decks/:id/prepare-images`，091 `ppt_deck_pages.pending_images_json`）：
  按规划里那几格逐格从素材库挑一张（不花钱）或 AI 现生一张（一次真实花费），存在那一页上，
  HTML 还没生成也能备。** 七条是承重的：**那一列绝不能跟 `images_json` 合并**（后者是配图跑完之后
  的结果，`savePageHtml` 会清掉它 —— 备好的图正相反，它在 HTML 之前就存在而且花过真钱，跟着一起
  清掉的话界面上只是「这一页又要重新配图了」）；`savePendingImages` 是 upsert 且**允许 `html=''` 的行**，
  于是 `GET /decks/:id/pages` 会回出这种行，它的 `previewHtml` **必须留空**、前端也不许把它当成
  「已生成」（照拼一份空 deck 的话右边是一块白，读起来像那一页排版塌了，而它压根没生成过）；
  **整份数组覆盖、`index` 从 1 起对齐规格**（逐格改的话「清掉第 2 格」之后剩下那张会顶上去，
  回填时贴到第 1 格，图文不符而页面渲染正常）；**重新规划照旧连它们一起删，但要回 `clearedImages`**
  并说「图还在素材库里可以挑回来」（不说的话他以为那几次额度白花了）；**素材库挑来的那张比例/画风
  和这一格不一致既不拒也不进 `problems`，改成那一格的标签一直显示**（`PptPlan.vue` 的 `spec-meta` /
  `prep-meta`：格子的比例和这张图的比例并排写着，不一致时跟一句「会裁掉一块」）—— 他是看着那张卡上
  的「16:9 landscape · 画风 S-B」自己点下去的，报成「这一页有 N 处注意」的话每挑一张多一条，
  把版式塌了/还是占位图那种真问题冲下去，而那个把手是这一页唯一的报警；反过来完全不显示的话
  3:4 贴进 16:9 被 `cover` 裁掉两边，构图缺一块看起来像模型画得不好。老页面存下来的那几条由
  migration **094** 从 `problems_json` 里删掉 —— 只改代码不够：`pastePrepared` 刻意沿用原来那几条
  （见下面那条），所以那两行会永远挂在他现在这一页上；
  规划里没有 `imageSpecs` 或 `index` 越界一律 **400 说清原因**，不当成「这一页没有图要备」回空数组
  （那样界面上是「备图完成、0 张」而他等的是几张图）；**界面上必须一直写「备的图还没贴进页面」** ——
  看到缩略图就以为这一页配好了的话，他会直接去拼整份，那几格还是占位图。
  生一张图的那一段（扣额度 → 渲染画风提示词 → 生图 → 写 `ai_logs` → 进素材库）是
  `imageService.runOneImage` 一份，备图和配图共用：各写一份的话其中一条早晚漏掉扣额度/日志/素材库，
  三样漏掉都不报错。比例的文字说法同理只有 `ratioText` 一份（各写一份的话同一句 subject 在两条路上
  生出来的一张横的一张方的）。
- **生成 HTML 是「一页一次调用」（`pageService.ts`，`POST /api/ppt/decks/:id/pages`），只带那一条版式的
  `buildText`。** 单条骨架近 8000 字，22 条一起带的话客户内容被挤到上下文末尾，出来照样是一份完整的
  HTML，只是内容开始跑偏 —— 没有一处会喊。跨页的事已经在 plan 那一次调用里定完了。
- **整份统一的那段要求在 `ppt_decks.notes`（093），每页生成都带上，和页级那段（092）
  两段一起发、不是二选一。** 页级有就顶掉整份那段的话，他在某一页补一句「这里的表格用等宽
  字体」，整份定的「语气克制、不要感叹号」就在这一页悄悄失效了 —— 只有那一页语气不一样，
  没有一处会说。prompt 里两段各带标签（「整份统一」/「这一页额外（冲突时按这一条）」）：
  合成一段的话两条冲突时模型挑哪条全凭运气，而出来是一页完整正常的幻灯片。上限和页级
  **同一个数**（`MAX_PAGE_NOTES_CHARS`，两处两个数的话整份里写得下的那段复制到某一页会被拒，
  他看不出是哪一边的限制）。界面上两处都必须显示：改整份那段**不会自动重排已生成的页**
  （它们还是按老要求排的，画面上看不出来）；页级对话框里也要把整份那段摊出来，不然
  「这一页什么要求都没有」和「这一页跟着整份走」分不开，他会在每页把整份那段再抄一遍。
- **每一格图的提示词用户可以改写，失焦就写回 `plan_json`**（`prepare-images` 的 `subject` /
  `from='subject'` → `deckStore.updatePlanImageSubject`），**入口和逐格备图一起放在「生成前确认」
  那个对话框里。** 模型写的那句常常不是他要的（「一张相关配图」「示例产品」），
  而这一格生出来的图看起来永远是「一张正常的图」，没有一处会说它画错了主题。四条是承重的：
  **必须落库**（只留在输入框里的话下一次「AI 生成」/配图用的还是模型原来那句，界面上两处不一样
  而都读起来正常）；**不能走 `savePlan`**（那个会删掉已生成的页 —— 改一句提示词就扔掉十几次已经
  花过的调用，而界面上只是那几页变回「还没生成」）；**空的/超 `MAX_SUBJECT_CHARS` 一律拒**
  （空提示词那一格会一直停在占位图上；截断的话他写在后面那几个条件一处都不生效）；
  **那一格已经备好的图不会跟着改**，所以只存提示词时要说一句「那张是照上一句生的，要重画得点
  AI 生成」——不说的话提示词写着 A、图是 B，两处都读起来正常。响应回 `imageSpecs` 让前端覆盖内存
  里那份规划（不覆盖的话对话框关掉再开是旧那句）。**图的入口必须在这个对话框里**：只放在右栏
  详情里的话他点了「开始生成」才发现图位全是占位图，而那次调用已经花掉了。
- **就地改文字：生成那一步给每段文字打上 `data-eid`（`pageEdit.injectEids`，跟着 html 一起存），
  预览 iframe 里双击改完失焦，前端只回「哪一块 + 改前那句 + 改后那句」，改 html 全在服务端
  （`POST /decks/:id/edit-text` → `applyTextEdit` → `savePageEditedHtml`）。** 六条承重：
  **编号存进 html、编辑时不按「第 N 个元素」重算**（重算的话改一次文字编号就可能漂一位，
  下一次编辑落到隔壁那一块上，而两块都是正常的文字）；**不收整份 html**（前端一次 DOMParser
  往返可能把引号/自闭合标签/实体全换一遍，页面照样渲染 —— 那种改动看不出来，直到导出的文件里
  某一块塌了）；**`oldText` 对不上就拒并说出「现在库里是哪句」**（拿旧画面覆盖 = 把另一处的
  改动悄悄擦掉）；**`<` `&` 一律转义**（不转的话从那个字符到块尾被当成标签吃掉，那一块少半句话
  而接口 200）；**只写 html 这一列**（走生成那条存法会把配图记录和 problems 一起清掉 ——
  改个标题就把「3 张图都配好了」擦掉，界面上只是「已保存」）；**存失败要把画面退回库里那一版**
  （前端靠 iframe 的 `:key` 重挂 —— 留着他刚打的那句的话屏幕上一切正常而库里是旧的，他会直接去导出）。
  两处坑：混排块（`<div>CONTENTS<span>目录</span></div>` 的外层）不给 eid、双击时要出声说明
  （静默 = 「这块不能改」和「双击没反应」在屏幕上是同一个样子），以及**编辑时要打开骨架自己的
  `body.editing`** —— 不打开的话 template 那个全局 keydown 会把空格 `preventDefault` 掉
  （**打空格打不出空格**，屏幕上一点提示都没有）、方向键翻页、单击画面 `go(cur+1)`。
  编辑脚本只塞进**这一个正在编辑的单页预览**：塞进导出文件的话别人也能编辑，而改动只留在
  他自己的浏览器里，看起来像存下来了。已经生成过的那几页由 **migration 095** 补 eid（纯函数、
  不联网、幂等）—— 只改生成那一步的话，老页面上双击一个字都改不动，而那一页读起来完全正常，
  唯一的出路是每页重新生成一次（十几次真实调用）。
- **浮动条：单击选中一块字（`data-eid` 那些），改颜色 / 字号 / 字重 —— 写成那个开标签上的
  inline style，点一下立刻存（`POST /decks/:id/edit-style` → `applyStyleEdit` → 同一个
  `savePageEditedHtml`），不调 AI。** 五条承重：**颜色只收服务端白名单
  （`COLOR_PALETTE`，`GET /edit-palette` 下发，前端不自己写一份）**且有测试核每个 `var(--…)`
  在 `template.html` 的 `:root` 里真有定义 —— 编出来的变量名会让浏览器把**整条声明**丢掉
  （字色掉回继承色、接口 200，看起来只是「点了没变色」），硬编码色值同样拒（换肤那天它不跟着变，
  而那一块读起来完全正常）；**字号按 `getComputedStyle` 的 px 加减**（em/百分比是相对父级的，
  父级本来就大一号时「点大一点」会渲染得更小），8–400 之外拒（太小看不见、太大顶出
  `overflow:hidden`，两种都不报错）；**认不出的属性/空 patch 一律 400**（静默忽略 = 他点了按钮
  画面一点不变、看起来像按钮坏了，而接口回 200）；**原有的 `style="…"` 是改写、不追加第二个**
  （浏览器只认第一个 —— 库里是新值而画面一点变化都没有）；**只动 inline style，不碰那一页的
  `<style>`**（改整份 CSS 的话一次「这行字大一点」会波及每一页上同一个类）。
  两处前端坑：浮动条挂在 `body` 上而不是 `#stage` 里（`#stage` 被 `scale()` 缩过，挂进去窗口
  小一点它就成了几个点不中的小方块），以及**选中的 eid 不能是 ref** —— `editSrcdoc` 读它，
  做成 ref 的话每选一块字整个 iframe 重挂一次，画面闪、选中框丢，看起来像浮动条自己弹掉了；
  存完之后那份预览是重挂的，所以要把它选回来（不选回来的话「再大一号」每次都得重新点那块字，
  看起来像浮动条只生效一次）。翻页时要清掉它：同一个 eid 在另一页上是另一块字，
  浮动条会吸到一块他没选的字上面。
- **对齐（⇤ ⇔ ⇥）走的是两个键：普通块发 `textAlign`，这一块本身是 flex/grid 的就发
  `justifyContent`（前端按 `getComputedStyle().display` 挑）。** 只发 `text-align` 的话，
  flex 那种块上浏览器**根本不认**这条声明 —— 接口 200、库里明明写着 `text-align:center`，
  而画面一动不动（看起来像这三个键坏了）。还有一种一样的现象但成因完全不同：**这一块的宽度就是
  文字本身的宽度**（flex 里的项目常这样），那时左中右都不会有变化 —— 前端量了
  `getBoundingClientRect` 和内容 Range 的宽度差，差不到 2px 就跟着这次改动回一句
  「画面上看不出变化，要选到外层那一整块去改」。不量的话这两种情况在屏幕上是同一个样子，
  而解法一个是换属性、一个是选外面那一层。
- **整块的对齐（`align-items`）是另一条接口 `edit-region-style`（`applyRegionStyle`）：容器没有
  `data-eid`，按「从 `section` 数下来的孩子下标路径」定位，再拿这一块里那串 eid 交叉核对。**
  不核的话浏览器和库里差一层时对齐写到了隔壁那一块上 —— 页面照样渲染、接口 200，只是他点的
  那一块没动、另一块动了。四条承重：**那三个键只在「选中的这一块自己是 flex/grid」时出现**
  （`bar[data-flex="1"]`，按 `getComputedStyle().display` 判）—— block 上写 `align-items`
  浏览器压根不认，露着的话就是「存上了、一点没变」；**图标按 `flex-direction` 重写**
  （row/grid → ⤒ ⇕ ⤓ 上下，column → ⇤ ⇔ ⇥ 左右），写死「顶部/底部」的话 column 方向上他照着
  图标点、内容往另一个轴动，而那一页读起来完全正常；**值只收 flex 认的那几个**
  （`flex-start`/`center`/`flex-end`/`stretch`/`baseline`，`left` 这种一律 400 —— 浏览器会把
  整条声明丢掉）；**存完要按路径把这一块选回来**（`__SELPATH__`，容器没有 eid 所以选不回 `SEL`
  那条路）—— 不选回来的话改一次对齐选中框就没了，再点得重新往外选好几层，看起来像这三个键
  只生效一次。`ralign` 在 `apply()` 里要排在「容器不能改样式」那条早退**之前**，排后面就是
  点了没反应。
- **「取消对齐」（⦸）发的是 `alignItems: null` —— 删掉那一条 inline 声明，不是写
  `align-items:unset`。** inline 的 `unset`（`initial`/`revert`/`normal` 同理）会**盖住**这一页
  `<style>` 里那条、把它按成「拉满」，而版式里写的可能是 `center`：他点的是「取消」，屏幕上却是
  第三种样子，而页面照样渲染 —— 所以这几个词一律 400 并指到 `null`。**本来就没有这一条时也要拒**：
  删一个不存在的东西 html 一个字不变，接口 200 加一句「已存」，看起来像「点了取消没反应」，
  而真正的成因是这一块的对齐来自这一页自己的 `<style>`（前端按 `el.style.alignItems` 把这个键
  调淡，但仍会发出去 —— 拦在前端的话他连成因都看不到）。回给界面的 `prev` 是刚删掉的那个值，
  不说的话那一整块跟着版式变了样而他不知道该点回哪个键。删到一条不剩时 `writeStyle` 把整个
  `style` 属性摘掉（留个 `style=""` 不影响渲染，但下次翻 html 时那一块看着像还有 inline 样式）。自闭合标签写 inline style 前要摘掉末尾那个 `/`（`… / style="…">` 会被浏览器
  当垃圾属性丢掉，页面照样渲染而这次改动无声无息）。
- **区域选中（纯前端，为「AI 编辑」准备范围）：hover 描出鼠标底下那一块，点两段字之间的空处就
  选中那一整块，「⤢ 选大一点」往外一层、「⤡」退回来（有回退栈）。** 四条承重：**往外只走到这一页

  中文」这条校验就废了（分不出哪句是原文、哪句是它编的）。

  于是双击的第二下落在缩过之后的画面上、点到的是别的元素，现象是**「双击改不动文字了」**，

  只准出现一次，而且位置要和 demo 片段一致**（在 `.slide-inner` 里还是直接挂在 `.slide` 下，两种都行，

  要么学会无视它，于是真塌的那一页也跟着被无视。反过来把整条去掉也不行：真的类名拼错时那一块回到默认

  里一块白读起来像这个版式渲染塌了），三种成因（空返回 / 截断在 `<section>` 之前 / 压根没按格式回）分开
  说且带思维链 token 数；缺 `</section>` 的补上闭合**并喊截断** —— 浏览器容错会照样渲染，下半页没了和
  「这一版设计得比较空」在屏幕上分不开。生图还没接，图槽位只能用 `/ppt-cases/ph-*.svg`，每个图元素带

  类名，模型写一个角标出来 `checkPage` 一句话都不说，改回样式或者换个容器它就又冒出来了（L13 那类版式右

  否则前端那句「已保存」是假的。所有查询都带 `user_id`（少了它，另一个账号的 deck id 读/改到的是他的
  稿子，而响应完全正常）。
- **规划结果落库在 `plan_json`（整份 `PlanResult` 原样存），`savePlan` 在同一个事务里把旧页删掉，
  并把删了几页回给前端显示。** 不删的话上一版生成好的「第 3 页」会挂在新规划的第 3 页下面，版式对不上
  内容而两边都不报错；删了不说的话他不知道自己刚扔掉十几次已经花掉的调用。
- **进 `/ppt/decks/:id` 时「一页都没规划过」才自动跑一次规划**（`PptPlan.vue` 的 `onMounted`），
  并且界面上要说明这次是自动跑的。每次进页面都跑 = 刷新一下就是一次真实调用**且清掉已生成的页**，
  而现象只是「怎么又在规划」；不说是自动跑的话，他会以为那是打开页面顺手渲染的东西，直到某天 429。
  新建页那句话同理必须写「进去会自动规划一次」—— 写成「不花额度」的话他会连建三份试试看。
- **规划用的提纲取库里那一份（`POST /decks/:id/plan` 不收 body 里的 outline），前端存不上就不许跑。**
  收 body 的话那个还没保存的编辑框成了事实上的提纲，「库里存的」和「刚规划的」是两份，
  下次进来重新生成的是另一份内容的页 —— 两边都正常返回。
- **生成/配图/拼整份/导出四条全部改成 deck 作用域（`/decks/:id/pages|images|deck|export`），
  输入一律从库里读，前端只传页码。** 原来那四条收前端回传的 html 和规划行 —— 那样前端内存里
  那份（上一次规划的行、重新生成前的旧 html、少一页的数组）就是事实上的输入，产出每一页都好看、
  只是和这份稿子对不上，四条路径都不报错。生成完/配完图**当场落库**，存不上要明确报错并说
  「这次调用已经花掉了，刷新看看，别直接重试」（静默丢 = 他刷新回来看到「还没生成」，再花一遍）。
  配图**部分成功也存**（成功那几张是真花过钱的）。`savePageHtml` 会把那一页的 `images_json` /
  `image_style_id` 一起清掉：重新生成的 HTML 里图槽位是占位图，留着配图记录的话界面上那一页
  照旧写着「3/3 张有图、画风 S-A」，而预览里只是「这版设计得比较空」（`deckStore.test.ts` 有断言）。
- **前端那句「哪些东西存下来了」是承重的**（`PptPlan.vue` 顶栏的 `saveLabel` + 抽屉里那行 `.dr-note`）：每一页都是一次真实
  调用，他要能确定关掉页面回来还在，不然只能靠再点一次生成来确认，而那是重新花钱。
  已生成的页读不进来（`GET /decks/:id/pages` 挂了）也要出声 —— 静默当成「还没生成」的话，
  界面上是「生成全部 12 页」，而那十几次调用已经花过。
  保存失败一律显示原文（静默失败 = 他改完提纲走了，下次回来是上一版，中间界面上什么都没说），
  画风必须**在拿到 `/styles` 清单之后**再按库里那条覆盖 —— 反过来缺省那套会盖掉他存过的画风，
  而下拉里显示的是缺省值，看起来像他自己选的（下一批图于是换了笔触，没有一处报错）。
- **工作台是「左缩略图菜单 + 右边一整页」（`PptPlan.vue`），不是十几行竖着排下来。** 四条是承重的：
  没生成的那一页缩略图/大画面放的是**那个版式的效果 demo**，必须灰掉并盖一句「不是这一页的内容」
  —— demo 本身是一张排得很好的页，不盖的话他以为这一页已经生成了，然后去拼整份（那边 400 说缺页），
  或者直接把「示例企业 · 示例数据」那一版当成自己的稿子；每页的状态（未生成 / 生成中 / 图 x/y /
  出错 / N 处问题）只在左边那条上，右边只显示当前页的详情（理由、要点、逐张配图、problems、HTML）；
  缩略图 iframe 要 `pointer-events:none`（deck 自己在 document 上挂了「点一下翻页」，不掐掉的话点
  缩略图不切页，界面毫无反应），且**不要**再叠 `transform: scale()`（deck 的 `fit()` 已按 iframe 视口
  缩放，缩两遍是贴在左上角的一小块）；「整份放映」是左边最后一项，够页数时点进去直接拼一次（不花额度），
  缺页时**不给拼**并说明缺几页。提纲/品牌/画风/重新规划收进右侧抽屉（提纲空着时自动打开 —— 空工作台上
  没有入口的话，「还没写提纲」看起来像页面坏了）；←/→ 翻页在输入框里不接管（接管的话他在提纲里按左右键会跳页）。
- **工作台锁成一屏（`.wb` 是 `height:100dvh; overflow:hidden`），大画面按「剩下的空间」缩放
  （`container-type:size` + `width:min(100cqw, calc(100cqh*16/9))`，水平垂直居中），详情移到右栏。**
  按整栏宽度铺开 16:9 的话它比屏幕高，看一页要滚一次，而滚下去之后顶栏那几个按钮（生成剩下的 N 页 /
  配全部图 / 导出）和左边那条缩略图全在视口外 —— 界面上不像出错，他只会以为「这些操作没有入口」。
  用 CSS 容器查询而不是 JS 量尺寸：量出来的值会停在上一次的窗口大小上（换屏/开抽屉之后画面偏一块，
  而 iframe 里那一页渲染完全正常）。三处**允许内部滚动**：右栏详情、左边缩略图那条、横幅区
  （`max-height:26vh` 自己滚 —— 不封顶的话十几条 problems 会把画面顶出屏幕，而封死不滚就只能看到
  前两条）。≤1000px 整块退回正常文档流（三栏挤在窄屏上时大画面只有指甲盖大）。
- **详情是浮在画面右侧、默认收起的抽屉（`.ins-dock`，整块平移、把手一直露在视口里），
  所以「收起来之后 problems 和生图失败的那几格全看不见」这条必须由两处补回来。**
  收起状态和「这一页干干净净」在屏幕上分不开，而那几行是「挑得准不准 / 图配齐没」唯一的依据 ——
  于是：**把手上带 `curIssues` 那个数字并整块转红**（problems + 报错 + 换了版式没重排 +
  还是占位图的格子数，少一类就是那一类永远不出声；把手做成一条灰缝的话这个唯一的报警等于没有），
  以及**同一页的问题数一变多就自动弹开** ——
  刚跑完的生成/配图那几条必须撞到眼前，不然他会拿着一份还带占位图的稿子去拼整份/导出，那两步都不拦
  （只在**同一页**内比较：翻页也弹的话每按一次方向键都要再收一次，他很快就不看它了）。
  摊开之后的内容本身**不再套第二层折叠**。≤1000px 不做浮层，接在画面下面（300px 的浮层会盖掉整块
  画面 = 画面和详情只能看一样）。
- **每张生成成功的配图都进素材库（090 `ppt_assets`，`services/ppt/assetStore.ts`，页面 `/ppt/assets`）。**
  一张图 = 一次真实的生图调用，而在这之前它只存在于**那一页的 html 里** —— 想在另一页/另一份稿子里
  再用一次，唯一的办法是去翻旧 deck 的 HTML 找 url，而界面上没有任何地方能看出「这张我生成过」，
  于是他会再花一次钱生成一张几乎一样的图，没有一处会提示。五条是承重的：**写在 `imageService` 的循环里、
  逐张写**（写在 api 层的话撞额度中断时前面那几张成功的图进不了库，而那几张是真花过钱的）；
  **写失败不能让这一页报错但必须出声**（图已经生成了，抛掉整页等于让他再花一遍；而静默的话素材库里
  少了几张，他只会以为「本来就这样」）；**存的 `prompt` 是槽位那句 `data-img-prompt`**，不是渲染完的
  整段画风提示词（整段里 90% 是画风模板，存它的话每张卡的文字都一样，挑图时分不出哪张是哪张）；
  `ratio`/`mode`/`style_id` 必须一起存 —— 那是「重用时会不会看出破绽」的唯一依据（3:4 的图塞进 16:9
  的槽位被 `cover` 裁掉两边、另一套画风混进来是笔触不统一，两种都不报错）；`UNIQUE(user_id, url)` +
  `ON CONFLICT DO NOTHING`（重复插的话列表里两张一样的卡，删掉一张刷新后图还在，看起来像删除没生效）。
  **删素材只删这一行**，COS 文件和已经用了它的那几页 html 都不动，所以确认框和 API 文档里都要写明
  「稿子里那几页不受影响」—— 不写的话他以为这是「把这张图从稿子里去掉」，删完去翻那份 deck 图还在。
  列表回 `total` + `pageSize` 两个数（只回前 120 张的话「就这些」和「装不下」分不开）；卡片上
  `storage='local'` 要标、`<img @error>` 要写出成因（破图和「这一格本来是空的」长得一样）。
- 首页卡片是 `home_modules` 表里的一行（后台 > 首页模块 自己加），不在 `Home.vue` 里写死。
