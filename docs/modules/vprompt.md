# 视频提示词优化（/vprompt）

- **方法论在 `skills/video-prompt/`：`base.md` 整份当 system prompt，题材附加规范（fight / acting / chase / stage）按需追加，
  任何一份读不到直接抛错。** 空 prompt 时模型照样回一份格式齐全的「优化稿」，只是一条规则都没用上。它们提炼自一个具体作品的
  导演方法论，**原作品的角色/道具不许进来**（`skill.test.ts` 扫关键词）—— 漏一个，模型就往用户的提示词里塞那个道具。
- **题材没选时，加载哪份附加规范由代码按原文关键词定（`options.ts` 的 `resolvePacks`），并把命中的那个词回给页面。**
  让模型自己判断的话它说「按打斗处理」却没拿到打斗规范；不显示的话打斗戏按日常规则改了，结果照样读起来很正常。
  关键词误命中只是多加载一份规则，漏命中才是问题 —— 往 `keywords` 里加词，不要改成「不选就全加载」（system 会长一倍）。
- **时间段模型排、代码核（`checkShots`）：从 0 开始、首尾相接、结束在总时长、每段 ≥1 秒、用户指定的镜头每个都用到。**
  不合规就带着具体问题重排一次，再不对整份报错 —— 不在代码里「拉齐」，因为那一段的画面是按错的秒数写的。
  运镜模板名一律按编号从 `cameraTemplates.ts` 取，不用模型报的名字；编号不存在时不标并写进 `notes`。
- **「优化后的提示词」是一整段、按维度分栏（镜头·运镜 / 场景·道具 / 空间·站位 / 动作·神情 / 环境连锁反应 / 运动物体 / 声音），
  里面的秒数一律由代码按核过的 shots 加（`final.cameraByShot` / `blockingByShot` / `actionByShot` 与 shots 一一对应，`checkFinal` 核条数），
  模型那边只写内容不写时间。** 让模型自己在正文里写「1.3s 切…」的话，时间轴核过了、正文里的秒数却是另一套，两边都读得很顺。
  条数不对就和时间段不对一样重排一次；开头残留的「0–1.3s：」由 `LEAD_TIME` 剥掉，否则复制出来每条两遍时间。
  `fullText`（复制用）由 `renderFinalText` 拼，和页面渲染是同一份数据。
- **完全免费：`unmetered: true` 只跳过 `ai_quota` 日额度，应用额度和 key 点数照旧。** 两个 gateway 入口和 `jsonGateway` 都认；
  失败话术也跟着不说「额度已经扣了」（`jsonFailMessage` 的 `unmetered`）。被刷时的手段是后台给 `vprompt` 配应用额度，
  或改 `app.ts` 那条每分钟 10 次。
- **前端有 400 秒的硬超时（`CLIENT_TIMEOUT_MS`），到点就报「连接多半断了，直接再点一次」。** 开发时后端重启、反代断开，
  fetch 可以一直挂着不报错 —— 页面上就是一个永远在转的「分析中」。这个数要大于服务端最坏耗时（一次 180 秒 + 重排一次 180 秒），
  调小了会把正常的慢调用误报成断线。
