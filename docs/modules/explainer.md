# 代码动画视频（/explainer）

- **画面不是模型写的代码，是代码按「场景 JSON」画的。** AI 只写每镜讲什么、画哪几个图标、谁指向谁、大致秒数；坐标、时间戳、镜头、排版、字号全在
  `components/explainer/scene.ts` 的 `compile` 里算。让模型给坐标的话字压在线上、出画面也不报错；给时间戳的话几镜加起来对不上总时长。`seconds` 只当比例，按 `duration` 归一。
- **场景 JSON 风格无关，白板（`whiteboard.ts`）和蓝图（`blueprint.ts`）读同一份编译结果（Plan）。** 风格专属的东西只有两处：`compile` 里按 `style` 加的蓝图中心线 / FIG 编号 / NOTE 框，
  和两个渲染器自己的质感。往 Plan 里加字段时两个渲染器都要认，只认一个的话另一种风格那部分悄悄不画。
- **编译时发现的问题一律进 `plan.notes`，页面上要显示：** 缺图标（画成虚线问号框）、字号缩小、折行超出格子、箭头指向不存在的元素、没有笔顺数据的字（退成手写体字体）、
  内容多时间短。不说的话画面「看起来能用」，而那个位置是空的 / 字小得看不清。
- **图标名只认 `geometry.ts` 的 `iconCatalog()`（自定义组件 + broll 的 `iconLibrary` 那批 Lucide），AI 以后从同一份表里挑、服务端逐个核。** Lucide 的 path 用浏览器的
  `getPointAtLength` 采成折线，一条 path 里有几段时在跳点处断开 —— 不断的话两段之间多出一条线。
- **汉字笔顺走 `GET /api/explainer/strokes`（PUBLIC），按需取、页面里缓存。** 导出渲染页不带登录，判成 protected 的话导出时所有汉字退成字体，而导出照样「成功」。
- **画面只由 t 决定，随机感一律固定种子（`rng(seed)`），不用 `Math.random` / CSS 动画。** 以后导出是无头浏览器逐帧截图，否则旧字迹、手抖每帧乱跳。
- **一块 canvas 只能拿一种 context（白板 2D / 蓝图 WebGL2），播放器换风格时换一块（`canvasKey`）。** 复用同一块的话第二种风格拿到 null，画面停在上一种风格的最后一帧。
- **字母 / 数字用内置的 Architects Daughter（OFL，`client/public/fonts/explainer/`，许可证在同目录），中文标点和 × → ≈ 这些符号按笔画写（`scene.ts` 的 `SYM`），蓝图标题栏的字在编译时写成「0 秒前就写好」的笔画。**
  都是为了不靠服务器上有没有中文字体：靠的话 Linux 上导出的标点 / 标题栏是方框或别的字体，导出照样「成功」。字体加载后用量宽度核一遍（`loadHandFont`），没生效进提示。
  笔顺库里没有的生僻字才退到中文字体（会进提示）。
- **剧本（第一步 AI）是给人看和改的自然语言：标题、画面怎么呈现、要画的元素（名词）、注释、秒数比例；第二步才翻译成场景 JSON（挑图标）。**
  镜头数按时长由代码算（`targetShots`）写进 prompt；AI 写超了的字数 / 元素 / 镜头一律截断并进 `notes`（有测试）—— 悄悄截的话他看到的是一份「完整」的剧本，而标题少了半句、后几镜没了。
- **每镜起止秒数只有一个公式 `shotWindows`（scene.ts），剧本页时间线和编译画面都用它。** 各算一遍的话改了一边，剧本上写的「第 2 镜 3.6–8.9 秒」和成片对不上，两边都不报错。
- **剧本先存浏览器本地（`explainer:draft:v1`），存不进去要在页面上说出来（`saveDraft` 回错误文案）。** 不说的话他以为存了，刷新后花过额度的剧本没了。
- **第二步（剧本 → 场景）AI 只给 items / arrows，标题、注释、秒数由 `buildScene` 从剧本原样抄。** 让 AI 一起重写的话，他刚在剧本里改的字会被悄悄改回去。
  编的图标名改成文字、指错的箭头去掉、少回的镜头用剧本里的元素顶上，全部进 `notes`（有测试）。
- **服务端的图标清单 `services/explainer/iconCatalog.json` 是从前端两张表生成的（`node server/scripts/explainer-icons.mjs`）**，改了 broll 的 `iconLibrary.ts` 或 explainer 的 `PROPS` 要重跑。
  不同步不是静默的：AI 挑了前端没有的图标，画面是问号框、编译提示会报。
- **画面生成后剧本又改过，预览上方必须标红「还是旧剧本的画面」（`sceneFrom` 存生成时的 `scriptKey`）。** 不标的话他改了注释、看预览没变，以为是画面的问题。
  风格不在场景里（场景风格无关），切风格直接重画、不用重新生成。
- **导出 = 无头浏览器打开 `/explainer/render` 逐帧 `__explainerSeek(t)` + 截图 → ffmpeg H.264；渲染页和播放器走同一套 `prepare → compile → 渲染器`。** 改一边不改另一边的话导出和预览不一样而导出照样「成功」。
  渲染页没准备好（打开的是旧版前端）、自己报 `__explainerFail`、渲染途中页面报错，都要报错不出片；准备阶段的提示经 `X-Explainer-Notes` 回前端显示。
  蓝图是 WebGL2：Mac 上启动参数走 Metal，Linux 上是软件渲染（能画、慢）。生产环境渲染页由 Express 托管的 `client/dist` 提供，**改了前端要重新构建**，否则导出用的是旧画面。
- **参数化图示（`diagrams.ts`：圆点组 / 十格框 / 算式 / 形状 / 数轴）：AI 只给数量这类参数，形状和位置由代码算；参数在服务端 `readDiagram` 核，超范围改成文字并说明。**
  图标库里只有 broll 那批商业类图标，没有图示时「5 个圆点」「十格框」只能写成文字（作者实测的凑十法就是这样）。
- **一镜里一个图形都没画出来（全是文字 / 清单）要进 `notes`。** AI 按规则「画不了就用文字」时不会编图标名，于是缺图标那条提示不触发 —— 画面悄悄退成一屏字，而页面上什么都没说。
- **算式按代码算一遍（`checkEquation`），两边不相等进 `notes`（有测试）。** 8 + 2 = 11 读起来完全正常、画面画得出来，没人会逐个核。
- **写剧本的 prompt 里列出了引擎能画的东西（图标关键词 + 图示 + 文字 / 清单 / 箭头），并要求不写「移动 / 飞过去」这类动作。** 不列的话剧本写的是画不出来的画面（「2 那一堆用箭头移进十格框」），他看剧本时以为会有。
- **导出时只放行渲染页同一个域名的请求（`page.route`）。** `index.html` 挂着 Google Fonts / 广告 / 统计，服务器连不上 Google 时截图一直「等字体」到超时（实测）。broll 的导出器没有这一层，有同样的风险。
- **入口：`/explainer` 是介绍页（样片就是真引擎实时画的调试台场景），编辑器在 `/explainer/studio`（`meta.keyApp: 'explainer'`，没 token 送 `/explainer/key` 弹输 key）。**
  key 前缀 `EXP`，scope `explainer:key` 单独列在 `scopeGuard.ts`：编辑页新调一个接口时那里要一起加，漏了的话 key 用户点那个按钮是一句 403，账号用户一切正常。
  扣点：剧本 / 画面各 1 点（网关扣），导出 5 点（`POINT_PRICE.explainerExport`，失败解冻，有测试）。编辑页没有站点顶栏，key 模式的余额和充值在编辑页自己的顶栏上，不调 `/api/auth/me`。
- **镜头语法 v2：每镜有版式（`layout`，`layoutCells` 算格子）和讲解动作（`beats`：画完之后圈 / 划线 / 叉 / 勾 / 框 / 推近）。** 作者实测第一版「很呆板」：每镜都是同一个网格、画完就静止。
  版式不认识按 grid、动作对着不存在的元素去掉，都进 `notes`（有测试）—— 不说的话画面只是「少了一个圈」，看不出 AI 安排过。
- **中心发散（hub）是思维导图式：中间一个大格子，其余分左右两列；不往中间的上下挂。** 画面高度放不下上下各一个格子，挂了就压在中间那个上（实测「翻译」压在「大模型」上）。
- **白板换镜 = 镜头平移到下一块区域（0.75 秒），不画连接线（作者定的，试过「橙笔画线带着镜头走」后去掉了）。**
  推近（zoom）白板是推镜头、蓝图是在那一刻切特写；推近之后到下一镜之前不拉回，下一镜从推近的位置出发。
- **剧本是三步（`writeScript`）：创意方案 → 分镜（每镜标 `role` 叙事角色和 `layout` 版式）→ 代码检查 `lintScript`（开头不是钩子、结尾不收束、30 秒以上没有转折、连着三镜同版式、一半以上是平均分格、没写元素、每镜太短 / 太长），不过就带着问题改一轮。**
  只查代码算得准的，不让模型自评（自评永远说「很好」）。改的那一轮没回来时用第一版并说出来，不当成改过了；改完还剩的问题进 `notes`（有测试）。
  版式在剧本里定、剧本页能改，画面那一步照剧本的版式（AI 只在剧本没定时才挑）—— 不然他在剧本页改的版式到画面里被悄悄换掉。
- **售卖型 key 按实际调用次数扣点（网关的 `unmetered` 只免日额度、不免点数）：剧本 2–3 点、画面每 8 镜一组 1 点、导出 5 点。** 每次操作后页面上写出「调用了几次 AI、扣了几点」，价格说明也按这个写 —— 写「各 1 点」的话他看余额对不上。
- **时长到 3 分钟（`DURATIONS` 最大 180，`MAX_SHOTS` 30）：画面按 8 镜一组并行生成（一次写 30 镜的 JSON 容易截断，截断 = 整次作废）；某一组失败时那几镜用剧本的元素写成文字并说明，全失败才报错。**
- **导出是后台任务（`exportJobs.ts`，内存里、文件在临时目录，导完留 30 分钟）：POST 回 id，前端每 1.5 秒查进度、导完再下载。** 一个请求等到底的话 3 分钟的片子（5400 帧，本机约 140 秒）会撞 Node 的请求超时，而且等的时候页面上没有进度。
  服务重启后任务就没了，查询如实回 404（不回「还在导」）；扣点在任务结束时结算 / 解冻（有测试）。
- **白纸手绘（`sketch`）= 一镜一张图：镜头正好框住这一张（`Z = 1`），画完停住（留三成时长），下一镜硬切；结尾照样拉远看全部，这时才看得出一张张纸的细边。**
  元素格子整体往中心收 18%（大留白是这个风格的要求），图标标签是写在上方、带小箭头的批注，注释是贴着主元素的蓝色批注（放不下才退到右下角、不画箭头）。
  颜色：黑 = 主体、红（accent）= 重点 / 问题、橙（signal）= 箭头流向、蓝（`aside`）= 补充说明 —— `aside` 只有这个风格用，白板 / 蓝图按 signal 画。
- **风格 → 渲染器只在 `renderers.ts` 一处（播放器和导出渲染页都调它），服务端的风格一律过 `isStyle` / `STYLE_IDS`，帧数一律查 `FPS[style]`。**
  以前播放器 / 渲染页各写「是蓝图就蓝图、否则白板」，接口各写 `=== 'whiteboard' || === 'blueprint'`、导出总帧数写 `=== 'blueprint' ? 24 : 30`：
  加了新风格漏一处的话，要么预览对、导出悄悄画成白板，要么某一步是一句 400，要么进度条总帧数对不上。
- **白纸手绘线细，图示里的实心点（`diagrams.ts` 的 `blob` 是一条螺旋）在渲染器里按「小范围里绕了很多圈」认出来、按涂满的粗细画。** 不认的话每个点是一盘蚊香，白板上看不出这个问题（马克笔够粗）。
