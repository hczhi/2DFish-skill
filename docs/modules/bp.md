# BP 投资分析（/bp）

- **「材料披露」由代码核过才算：模型必须抄一段原文（`quote`），`buildCard` 去原文里找，找不到降成 `unverified`
  （界面「原文对不上」）；页码也由代码按引文位置算，不信模型报的。** 后面的竞品 / 对标 / 机构匹配都拿这张卡当事实，
  模型补出来的估值、融资额标着「材料披露」的话，下游每一步都当真往下推，报告读起来完全正常。
- **字段清单在 `SECTIONS`（代码里），模型漏掉的必有字段补成「未披露」；一个字段都没抽出来时抛错。** 不补的话
  「BP 没写」和「模型漏抽」都是那一行不存在；不抛的话一张全「未披露」的卡读起来是「这份 BP 什么都没写」。
  BP 有整页图片没读到字时（`emptyPages`）必须在 notes 里说「未披露」不可信 —— 那几页往往就是融资和团队。
- **超过 `MAX_BP_CHARS` 只拒不截。** 截掉的后几页上的字段会显示成「未披露」，是一句合理的假话。
- **报告是后台任务（`bp_reports`，120），一章跑完写一章（`saveSection`），新章节要同时加进 `reportRunner.STEPS`。**
  整份跑完才写的话后面某章挂了，前面已经花了额度的几章一起没了，界面只剩一句失败；不进 `STEPS` 的话进度列表上
  没有那一行，看起来像卡在上一章。启动时遗留的 running 由 `reapInterruptedBpReports` 标成中断，否则永远「分析中」。
- **5.11 一致性交叉表：冲突 / 一致要两段不同的原文都在 BP 里核得上，少一段整条丢掉（进 `dropped` 并显示），不降成「单点无对照」。**
  编出来的冲突读起来铁证如山，创业者会去改一个不存在的矛盾；降成单点的话那一行又成了「BP 只提过一次」，还是假话。
- **各章「分析方法」可在后台 /admin/skills 改（slot `bp-*`，内置默认在 `bp/methods.ts`，121 播种），输出格式和核验不在里面。**
  `methods.ts` 是纯常量（migration 也 import 它），别往里 import 碰 DB 的模块。每章把 `promptSource` 存进报告、页脚显示：
  后台那份被停用 / 解绑时静默退回内置默认，不显示的话改了看不出生效没。
- **5.12 收入质量：模型只摘原始数字（`raw` 原样带单位 + `quote`），单位换算、月数、比率、阈值、缺口全在 `revenueService` 代码里。**
  `raw` 不在引文里 / 引文是预测数（「预计」「目标」…）/ 没单位的金额一律不采用，并在界面上列出来 —— 不列的话「BP 写了但没核上」
  和「BP 没写」都是「未披露」。累计月数由代码从引文的两个「YYYY年M月」算（模型会把「2023年」读成 2023×12）。
- **06 宏观分析：模型只引资料编号，URL 由代码按编号填；数字（value / delta / 趋势证据里的）要在被引那几条的原文里出现，否则 `unsourced`。**
  模型自己写链接 / 来源名的话能编出一个不存在的出处；不核数字的话「102 亿 [1]」和「3126 亿 [1]」显示得一样可信。
  检索词由代码按事实卡「所属行业」拼（没抽到就整章报错，不拿公司名去搜 —— 搜回来的是它自己的新闻稿）；
  部分检索词失败列在 `failedQueries`，全部失败整章报错带原文。
- **07-09 的名字（竞品 / 对标企业 / 投资方 / 机构 / 合伙人）都要在被引资料原文里出现（`sources.nameBacked`），否则丢掉并进 `dropped` 显示。**
  编出来的竞品、领投方、合伙人读起来和查到的一样，而创业者会拿着去写 BP、托人引荐。合伙人查不到时清空并留下
  `partnerRejected`（不留的话「资料里没有」和「模型没给」都是一个「待核实」）；09 的 confidence 由代码按这两条定。
  融资轮次的被引资料里必须提到这家竞品本身，否则是把别家的融资挂到它头上。
- **各章资料编号独立，前端锚点带章节前缀（`#src-ind-3` / `#src-comp-3` / `#src-inv-3`）。** 共用一套锚点的话 07 章点 [3]
  跳到 06 章那条，读者核的是另一篇文章。同章第二轮检索（竞品融资）用 `gatherSources({ startAt })` 接着编号。
- **01-02 评分：模型只给五维 fact / proof（0-100），总分 / 可回收 / 梯队（85·75·60）/ 四象限全在 `diagnosisService.scoreDims` 算；
  缺一维直接报错。** 模型在文字里写了分数时 `scoreInText` 置上、界面提示以系统算的为准（skill 那条「标题 61.8、正文 309」的口径事故）。
  没有同批 BP，`benchmark` 写死「无同批基线」，不让模型编一个分位。
- **后面几章的输入是前面几章核验过的结果（`context.ts`），不是让模型重读 BP 全文。** 重读的话 5.11 已经丢掉的那条
  编出来的冲突会被再「发现」一次，写进扣分和改写建议里。03 的改写建议原句同样要在 BP 里核得上，否则丢掉计数。
- **断点续跑 = 同一个 `runReport`，已在 `result_json` 里的章节跳过、拿存下来的结果当后面几章的输入；开跑条件写在 UPDATE 里（`reopenReport`）。**
  重跑前面几章的话不只是白花额度：模型这次挑的竞品不一样，后面已经跑完的评分就和前面对不上了，而两边各自读起来都正常。
  先读再写判状态的话双击会起两条流水线，每章扣两次、后写的盖掉先写的。跑着的报告不许删（删了之后下一章无处可写，额度照扣）。
- **5.9 企业信用档案：被引资料里必须出现公司全称，否则那条引用剔掉（`otherCompany`）；查不到的那句话由代码写「公开网页未检索到（不代表没有）」，
  模型写的「无 / 0 条」一律当没查到。** 同名公司的被执行记录、或者一栏「涉诉：无」，读起来都像查过。BP 没写全称时整章 `skipped`
  并说原因（拿简称查工商，搜回来的大半是别家）。这一章不打断流水线 —— 它不是后面任何一章的必要输入。
- **重跑某一章 = 清掉它和它后面所有章再跑（`rerunKeys`），事实卡不能重跑。** 只清一章的话后面的评分还是按旧竞品算的。
  事实卡的提醒已并进报告级 notes，重跑会重复一份，要换就重新上传。
- **报告页样式照 2026-11 那份报告模版；`/bp` 首页是海军蓝 + 暖金（`.bpr.home.pe`，顶部用公共 SiteHeader，fixed 50px，页面 padding-top 让出），全在 `client/src/components/bp/report.css`（规则都挂在 `.bpr` 下），组件不写 scoped 样式。**
  10.1 的「高 / 中 / 低」是模型给、服务端校验的 `priority`，缺了就不显示 —— 按条目顺序贴标签的话那个优先级是前端编的。
- **联网资料读整页正文（Tavily advanced + raw_content），给模型的是按关键词挑出来的段落（`pickPassages`），核验用整页。**
  只给 700 字摘要时关键数字经常不在摘要里：要么那一节空、要么照半句话理解错口径、要么被标红。段落一个都没挑中时退回取正文开头 ——
  返回空串的话这条资料（尤其用户补的研报）会被整条跳过，而他以为 AI 读过（有测试）。
- **来源按域名分级（`tierOf`），编号顺序、资料预算裁剪都按它；数字的 `xsrc` = 出现在几个不同域名的正文里，界面标「N 源印证 / 单一来源」。**
  同一域名多篇只算一个，年份不算可比数字。认不出的域名归 3 不归 4（官网、协会在这一档）。新增常见媒体改 `T1-T4` 那几张表。
- **检索词由 `keywords` 这一步从 BP 提炼细分赛道词（只出词、代码收格式）；失败不打断，退回「所属行业」并在 06 章顶部说出来。**
  直接用「企业服务」这种大词时，市场 / 竞品 / 机构三章都在讲一个大十倍的盘子，而每个数字都核得上出处。
  政策 / 技术 / 趋势 / 创业公司融资 / 机构动态这几类检索带 `recent`（近一年）；竞品融资历程不带（A 轮可能是十年前）。
- **补充资料（`bp_report_materials`，126）存抓下来的正文，不在重跑时再抓**：隔天再抓可能变了，界面上显示的和 AI 读的就不是同一篇。
  补了不自动生效，要「用补充资料重跑这一章」（连带后面章节）；用户资料 tier 0、不受预算裁剪；只拒不截（> 80000 字 400）。
- **补充材料（BP 之外的文件 / 图片 / 粘贴文字）拼进 bp_text，带「===== 附件K《名》 =====」分隔，附件页码单独一套（`--- 附件K 第 N 页 ---`）。**
  格式由 `attachments.composeBpText` 写、`quotes.splitPages` 认，两边必须一致；混成一套页码的话附件第 3 页那句被标成「BP 第 3 页」，他翻 BP 找不到。
  所有引文都带 `doc`（null = BP 本身），前端用 `where.ts` 显示。图片走 BP 自己的逐字转写（不复用咨询那条 —— 那条按类目重组语言，
  引文核验就核的是转述），在原文和 5.0 清单里标「图片识别」。任何一份读不出来整次报错点名（跳过的话它还列在界面上）；合计上限 `MAX_TOTAL_CHARS`，只拒不截。
- **对第三方开放（品牌咨询的 key / 嵌入版，128）：页面放在 `/consult/bp` 下，不在 `/bp`。** 嵌入版的 CSP `frame-ancestors` 只发给 `/consult*`，
  放在别处的话 iframe 里一刷新就是一块白，而每个接口都 200。归属键是 `(user_id, sdk_pk, external_uid)`（`reportStore.BpOwner`，必填参数，
  SQL 用 `IS ?`）—— 只按 user_id 的话同一个 pk 下 A 客户看到 B 客户的 BP（有测试）。scopeGuard 只登记了 `/api/bp/reports*` 一棵。
- **key 用户整份报告一次计费（200 点），靠 `core/llm/callContext` 的 `coversPoints` 让网关跳过按次扣点 *和* 日额度。** 只跳过前者的话影子用户
  落到 `checkAndDeductQuota`，被一个它没有的「10 次/天」挡住；整份不包上下文的话一份报告扣 200 又扣十几个 1 点。冻结额落库（`points_held`），
  结算 / 解冻和状态变更在同一个事务里、只结算一次（`charged`）；启动收尸先解冻再标中断 —— 不解的话那 200 点永远冻在 `app_keys.frozen`。
  上传时的图片转写也在上下文里、在冻结之后跑。嵌入版不扣点，`onAiCall` 每次调用给 pk 当日用量加一（失败也算）。
- **开跑闸门 `billing.admitRun`：pk 状态 → pk 额度预检（剩余 < 一份报告约 15 次就不开跑）→ 当日次数（带条件 UPSERT 原子加一）→ 冻结点数。**
  不预检的话跑到第七章撞上限，前六章白花钱、报告停一半；不封顶次数的话公开的 pk + 免费重跑能一个循环刷几百份（每份约 30 次联网检索）。
  点数不够 402 时那次计数退回。停用的 pk 在每个 BP 请求上都判（短 token 活一刻钟）。
- **分行业指标模板 + 分阶段标尺（129）：行业只能是 `standards.SECTORS` 里的键（keywords 那一步让模型选、代码校验，不认识的归 general），
  轮次由 `standards.stageOf` 从事实卡「本轮轮次」认（Pre-A+ ≠ A，认不出就 general 并写出原文）。** 行业专属指标同 5.12：模型只摘原始数字，
  公式 / 阈值 / 状态全在 `sectorMetrics`；BP 没给的照样列出来标「未披露」进缺口。阶段标尺是文字，后台每个轮次一个 slot（`bp-stage-*`）。
  报告上写明用的是哪个行业模板、哪个轮次标尺及依据 —— 不写的话判错了行业 / 轮次也看不出来。老报告的检索词没有 sector 时 runner 会重提一次。
- **5.10 团队：成员名单由代码从事实卡取（名字须在 BP 原文里），外部印证的被引资料里必须出现这个人的名字（否则丢掉计数）；成员核实状态和「外部验证」等级按留下的印证由代码定。**
  同名的人履历安到创始人头上，读起来是核实过的。
- **5.7 可信度：证据清单由代码从前面几章核验过的结果拼（`credibilityService.evidenceOf`），模型只能引编号；标了核实结论却没引到合法证据的降成「未核到」；评级按占比由代码算。**
  所以它在流水线里排在 credit / team / industry / competitors 之后。
- **09 融资方案：融资额区间（月均净烧 × 18–24）、跑道、隐含估值（融资额 ÷ 出让比例 − 融资额）、门槛差距、股东解析全在 `computeFinancing`；
  估值区间 / 出让比例 / 下一轮门槛来自「平台参考口径」（`benchmarks.ts` 缺省 + `bp_benchmarks` 后台覆盖，130），BP 没写轮次时不给区间。**
  模型只写建议文字，里面出现系统没算出来的数字列进 `numbersOutside` 并提示（亿 / 万两种写法都认）。门槛的 metric 必须是 5.12 能算的键，后台保存时校验 —— 写错的话那一行静默变成「无法对照」。
- **模拟路演已下线（接口、页面、`bp-pitch` 提示词槽位都删了），132 的 `bp_pitch_sessions` 表和 133 的种子留着没删**（迁移已在库里跑过）。
  要重新上线别直接复用旧表里的会话 —— 那批会话是按 30 点/场扣过钱的，计费逻辑已经没了。
- **报告页的状态灯（章节绿/黄/红）全由 `components/bp/health.ts` 从各章数据算，不调模型；样式类叫 `.ld` 不叫 `.dot`** ——
  `ul.dot` 是项目符号列表，同名的话列表被挤成一字一行，而且只在某几章出现，看起来像那章数据坏了。
- **十字图上只有本标的常显名字，其它公司悬停（触屏点一下）才出名字；图下的编号图例是唯一的完整名单，不能收起或隐藏** ——
  藏掉的话图上只剩一堆数字圆点，读者无从知道 4 号是谁。
- **演示版（`/consult/bp/reports/:id/deck`，报告页「演示模式」）只读已有报告数据，页面由 `components/bp/deck/slides.ts` 代码挑，不调模型、不扣点。
  没核实的条目（`unsourced` 的指标/趋势/对标、核不到金额的融资轮、别家公司的信用记录）直接不上页，而不是只藏掉「单一来源」提示** ——
  演示版不显示系统提示，只藏提示的话客户会把没核实的数字当事实听进去。没数据的页整页跳过，跳过了什么列在「总览」底部（讲解人要知道少了哪页）。
  全屏必须在报告页那次点击里请求（浏览器只认用户手势），在演示页 onMounted 里请求会被静默拒绝。
