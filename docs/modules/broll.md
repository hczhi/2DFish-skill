# 口播动效卡（/broll）

- **卡片的每一帧只由 t（秒）算出来（`components/broll/timeline.ts`），不用 CSS transition/animation。** 以后服务端导出是
  无头 Chrome 逐帧 seek 截图；用了 CSS 动画的话截图那一刻动画走到哪取决于机器快慢，出片抖、缺帧，而预览里一切正常。
- **口播视频不上传，只在浏览器里用 objectURL 播；字幕时间也只在前端。** AI 配卡只发「编号 + 原文」，模型只回字幕编号，
  入点出点由前端按那句字幕算（`placeCard`）。让模型回时间的话它会编一个看起来合理的秒数，卡片出现在错的那句话上。
- **AI 配的每张卡都过 `checkCards` 核原话：数字按「整个数」比（`300` 不算出现在「3000」里），单位必须在本句，说明必须是本句
  或前后一句的原文，前缀只许几个符号。** 核不过整张拦下、原因回给页面显示（`rejected`）。不核的话模型编的数字照样好看，
  没人会逐张去对原话。中文数字（「三百」）目前一律拦下，不做换算。
- **SRT 里读不出时间的段落计数报出来（`parseSrt` 的 `skipped`），不悄悄跳过。** 少了一句，那句上该有的卡就没了，而列表看起来是完整的。
- **AI 配卡不覆盖已经挂了卡的句子**，跳过的写进报告。覆盖的话他手改过的文字悄悄没了。
- **卡片位置存成占画布宽高的比例（`x / y`）+ 缩放倍数 `s`，「出画面」按 位置 × 卡片自然尺寸 × s 判断（`isOverflow`）。**
  卡片自然尺寸按**终值**量（跳数时用不可见的终值占位撑宽），量当前帧的话跳数中途数字更短，会漏报。
  不在当前时间的卡用 `visibility: hidden` 藏，不用 `v-if`/`display:none` —— 那样量不到尺寸，没播到的卡永远不标红。
- **标题类文字（章节标题、英文小标签、提问卡）允许 AI 概括，编辑器里标「AI 概括」可手改；数字、人名、引用、清单条目照旧核原话。**
- **颜色字体只走主题（`theme.ts`）的 CSS 变量，卡片里不写死。模版上线前要在调试台 `/broll/lab` 过一遍所有 fixtures，过了才把
  `templates.ts` 里的 `status` 改成 `live`。** fixtures 挑最容易崩的数据（超长数字、最长说明、非数字），不是好看的示例。
- **字体在不在用「量宽度」判断（`hasFont`），不用 `document.fonts.check`** —— 后者对本机没有的字体也回 true。主题字体本机一个都没有时
  浏览器悄悄换成默认字体，预览照样好看；导出在服务器渲染，服务器上没装同样的字体时导出的字和预览不一样，也不报错。
- **数据本身的问题走模版的 `check()`（如高亮词不在标题里、清单少于 2 条），面板、时间轴、调试台三处都要显示。** 卡片照样画、只是
  不高亮 / 很挤 —— 不说的话读起来像动画本来就这样。卡片停留时长下限按模版的 `minDuration(data)` 算（字数、条数越多越长），
  不是一个固定 3 秒：清单 5 条 + 结论要 4 秒多才出全，按 3 秒的话最后两条一闪就出场了。
- **模版上线状态存在 `broll_templates`（117），没有行 = 草稿；读失败时前端报错，不当成「全是草稿」。** 当成全是草稿的话，用户那边加卡下拉框
  是空的，读起来像本来就没有卡。AI 配卡在服务端也查一遍状态（目前只认 `number`）：只在前端过滤的话，调试台里下线了的卡用户照样能一键配出来。
- **AI 配卡的字段规则在 `server/src/services/broll/templateSpecs.ts`，字段名必须和前端 `templates.ts` 一致。** 对不上的话 AI 填的那一栏前端不认，
  卡片照样放上去、那一栏是空的。新模版前端加了、这里没加 = 不交给 AI，`notes` 里会说「还不支持 AI 配」。数字 / 单位只认本段（`line..endLine`）里的，
  文字认本段加前后各一句；可能分在相邻几句里的（清单、步骤、正误、对比）要标 `multiLine`，否则第二句里的那个数会被当成「原话里没有」拦下。
- **AI 配卡的张数目标由代码按句数算（`targetCount`，平均每 3–5 句一张）写进 prompt。** 不给的话模型极度保守（35 句只交 2 张），
  且会把「第一招…第五招」整段塞进一张清单（跨 21 句，超过 `MAX_SPAN` 整张作废）—— 用户看到的只是「AI 加了 1 张卡」。
- **章节编号优先用原话里的序号（「第三招」→ 03，`ordinalIn`）；整条里只要有一张说了序号，没说序号的那几张就不编号；整条都没说才按顺序 01、02。**
  只按顺序数的话，第二招被配成别的卡时「第三招」上显示 02；「最后的绝招」编成 06 是在替他说话 —— 两种读起来都完全正常。
  手动加章节卡时编辑页按同样的规则给编号（`chapterIndexFor`），不然每张都是默认的 01，导航条上一排 01。
- **带随机感的效果（粒子、漂浮符号）一律用固定种子的 `hash(i, k)`，不用 `Math.random`。** 用了的话同一个 t 每次画出来不一样，
  预览看着正常，导出逐帧截图时整屏粒子乱跳。全屏卡（`data.fullscreen`）铺满画布、不按 x/y/s 摆，尺寸用画布的 `--cw / --ch`。
- **底板材质（`CardShell.vue`）和强调字渐变 / 光晕（`material.css` 的 `.bx-hot`）所有卡共用一份，卡片里不各写各的。** 各写一份的话
  改了一张其余照旧，整条视频质感不统一。渐变和光晕由 `--accent` 用 `color-mix` 推出来 —— 写死成橙色的话，单张卡改了强调色只改了一半
  （字变色了、光晕还是橙的）。`.bx-hot` 是 `color: transparent` + 背景裁到文字，**不能再叠 `text-shadow`**（阴影会从透明字里透出来发脏），
  要光晕用 `filter: drop-shadow`。
- **多轨道：每张卡有 `track`，同一轨道上时间不重叠，画面叠放顺序 = 轨道号（上层盖下层，和剪映一致）。** 放卡 / 拖完之后撞车就往上顺延到空着的轨道，
  每次变动后 `compactTracks` 压掉空轨道。「上移 / 下移一层」被挡住时和挡住的那几张对调 —— 只会往上顺延的话两张叠着的卡换不了上下顺序。
  AI 配卡仍然不往已有卡的时间段里放（一次塞几张叠着的画面很乱），叠放是手动的。
- **卡片里的图片一律先传服务器（`/api/upload/image`，存 COS）再用，不用本机 objectURL。** 导出在服务器上渲染，读不到本机文件 ——
  用 objectURL 的话预览正常、导出那一格是空的，导出照样「成功」。缺图的位置画成虚线「待上传」并由 `check` 报出来，不画成空白。
  编辑面板里图片字段不能包在 `<label>` 里（label 里有多个控件时点哪儿都会弹出文件选择框）。
- **图片组每一项的入场时刻只有一个公式（`ImageGroupCard` 的 `arrive` / `templates.ts` 的 `igArrive`，两边必须一致）。** 调试台关键帧和
  最短停留都按它算；改了卡片里的节奏没改这边的话，「停住」那一格拍到的是还没落地的卡，最短停留也短了，最后一张一落地就出场。
- **主题不只管强调色：投影 / 高光 / 点阵 / 颗粒 / 图片位底色 / 压在强调色上的字色 / 光晕强度都是主题变量（`--shadow-c` `--hi` `--dot`
  `--grain` `--tile` `--ink-on-accent` `--glow-a` …），卡片里不许写死 `rgba(0,0,0,…)` / `#1a1410` 这类暗色。** 写死的话浅色主题（纸感）
  下米色纸面上是一圈很重的黑投影、白高光看不见，读起来像渲染坏了，而暗色主题下一切正常、发现不了。新加卡片时换到「纸感」在调试台里过一遍。
- **「怎么动」也跟主题走（`theme.motion`，经 `themeContext` 的 provide/inject 下发）：纸感用景深入场（`depthIn`），漂浮符号层由 `--glyph-a` 开关。**
  舞台（编辑页 / `CardStage`）必须 provide 当前主题 —— 漏了的话卡片按默认主题动，换了主题颜色变了、动法没变，看不出哪里不对。
- **放卡 / 换画幅时自动缩到放得下（`fitCard`），并把缩到多少写进 `fitNote` 显示出来。** 不说的话他只会觉得「字怎么变小了」。
  尺寸是渲染后才报上来的，所以新卡先进 `pendingFit`，等 `sizes` 里有了再缩。调试台只把「要缩到 60% 以下」当问题。
- **导出 = 无头浏览器打开前端 `/broll/render`（透明底，规则和编辑页画卡片一致）逐帧 seek + 截图 → ffmpeg（`ffmpeg-static`）。**
  渲染页和编辑页的摆放 / 缩放 / 全屏 / 叠放规则要一起改，改一边的话导出和预览不一样而导出照样「成功」。渲染页加载不出图片时报 `__brollFail`，
  服务器缺主题字体时报 `__brollFontNotes`（回到前端显示）—— 两种都不能截出来当成功。渲染页地址由 `BROLL_RENDER_ORIGIN` 决定：
  开发时 Express 托管的 `client/dist` 是上一次构建的旧版，没有这个页面，所以开发默认走 vite 5173。
- **导出只给两种 .mov：PNG 帧（`png`，兼容最广、约 10MB/秒）和苹果 HEVC 带透明（`hevc`，很小，只有 Mac 的 VideoToolbox 能编）。**
  ffmpeg 编的 ProRes 4444 文件本身是透明的（depth=32、苹果也认），**但剪映叠在口播上面照样是黑底**（作者实测），WebM 剪映读不了 —— 所以都去掉了。
  **PNG 和 HEVC 两种作者在剪映里都实测透明正常（2026-10-23）。** 改编码参数后要重新在剪映里验一遍：文件本身透明 ≠ 剪映认。
  HEVC 必须带 `-alpha_quality`（默认 0 = 不编透明层，导出来就是黑底）；服务器上没有 `hevc_videotoolbox` 时直接 400 让他改选 PNG，不悄悄回落。
  校验透明有没有编进去：ffmpeg 解不出 HEVC 的透明层，要用 macOS 的 `avconvert -p PresetHEVCHighestQualityWithAlpha`（它只对有透明的源接受这个预设）。
  要看 HEVC 透明层的像素：`avconvert -p PresetAppleProRes4444LPCM` 转成 ProRes 再用 ffmpeg 抽帧。
- **每个导出文件的第 0 帧左上角都有一块 8px、白色 4% 的标记（`exportService` 的 `__broll_alpha_mark`），不许删。** 剪映看开头的画面判断
  直通/预乘透明：那一帧里颜色都不超过透明度（全透明、或只有暗色半透明）就判成预乘，之后半透明的光晕/渐变全变成实心亮色块（去掉底板时最明显）。
  整条导出前面常是几十秒空帧，所以**单张正常、整条出问题，两个文件逐像素一样**（作者实测，卡片在 20 秒处）。透明度别再调低：HEVC 会把个位数的透明度压成 0。
  整条叠加层里没卡的帧直接塞一张透明帧、不截图；PNG 整条限 5 分钟。
- **原话里的中文数字也参与核对（`cnToNumber`：三百 / 一千二百八十 / 两万 / 三点五；「百分之四十」「四成」算 40 且认 % 单位）。** 换错的话上屏一个错的数，
  读起来完全正常，所以有测试。模型那边被要求把中文数字换成阿拉伯数字填。
- **顶部章节导航条不单独存章节表，直接按时间轴上的章节卡分段（`navChapters`）。** 两份的话改了章节卡导航条照旧。导航条开着时整条叠加层每一帧都要截图
  （没卡的帧塞透明空帧的优化不能用，否则导航条在那几段消失）。
- **人名条只能手动加（`MANUAL_ONLY`），不交给 AI。** 名字、头衔编错了读起来完全正常。
- **撤销按「停半秒记一步」（拖动时不会每帧一步），输入框里的 ⌘Z 留给输入框；画面拖动吸附画面边距 / 中线 / 字幕区上沿 / 同屏其他卡的边，按 Alt 不吸。**
- **图表类（柱状图 / 折线 / 漏斗）的 AI 字段走 `pairs` 规则：每项「名字 数值」，名字核原话、数值必须是本段原话里出现的数。** 柱高、点位、转化率、
  「立省 xx」、进度百分比一律代码算，不让模型算。仪表盘的满分常常不说出口（「打 8.5 分」），所以只许 5 / 10 / 100 三选一，不当原话核。
- **只能手动加的（`MANUAL_ONLY`）：人名条、窗口截图、弹幕、社交帖子。** 后两种默认带「示意」小标，关掉时 check 会提醒「确认是真实评论 / 数据」——
  AI 或用户编的评论、点赞数读起来和真的一模一样，观众会当成真实反馈。
- **SVG 里的 `id`（渐变、裁剪区）每个卡片实例要唯一（`uid`）。** 同页有几张同类卡时（调试台就是），id 一样的话后面几张用的是第一张的裁剪区，
  画到一半的进度对不上，而单张看是对的。
- **表情贴纸用系统 emoji 字体，服务器没装彩色 emoji 字体时导出会变方框 / 黑白；关注引导的图标是 SVG，不受影响。**
- **AI 配卡分两步：第一步只给目录（`category` 分组 + 卡名 + 什么时候用）挑卡型和字幕编号，第二步只带选中卡型的字段规则、按出现顺序分 ≤3 组并行填。**
  第一步定的 template / line / endLine 以它为准（第二步改了也不认），跨句超限 / 重叠在第一步就拦（不白填）；第二步没回、`skip`、整组失败的卡
  一律进 rejected 写原因（`mergeFills`，有测试）—— 悄悄少几张的话他只会以为 AI 就配了这么多。只有第一步扣额度，第二步 `unmetered`。
  新加卡型时 `category` 必填（TS 会拦），否则它进不了目录、AI 永远不会选它。
- **编辑页是 CSS grid 四行（顶栏 / 提示条 / 中间三栏 / 时间轴），每块用 `grid-row` 固定在自己那一行。** 提示条是 `v-if` 的，不固定的话它不在时
  后面几块整体上移一行：时间轴跑进 `1fr` 那行、被盖住，从卡片库拖过去的卡落不下来，而画面看起来只是「布局有点怪」。
- **卡片可以加在任意时间（`placeCardAt`），默认停留 = 模版的最短时长；从卡片库加的卡先用第一组测试数据占位，播放头正好在某句字幕上时再用那句预填。**
  空卡放上去什么都看不见，他不知道放的是什么。属性面板改「开始」= 整体挪（时长不变），改「时长」= 改结束；落到有卡的轨道就往上顺延一条。
- **对外入口：`/broll` 是介绍页，编辑器在 `/broll/studio`（`meta.keyApp: 'broll'`，没 token 送 `/broll/key` 弹输 key）。** key 前缀 `BRL`，scope `broll:key`
  单独列在 `scopeGuard.ts`（没有嵌入版可展开）—— 编辑页新调一个接口时那里要一起加，漏了的话 key 用户点那个按钮是一句 403，账号用户一切正常，你自测发现不了。
  **导出每次 5 点（`POINT_PRICE.brollExport`，不看时长）：参数校验之后冻结、导出成功才结算、任何失败解冻（`charged`，有测试）。** 失败也扣的话他看到「导出失败」而余额悄悄少 5 点。
  编辑页没有站点顶栏，余额和充值框在编辑页自己的顶栏上；key 模式下不调 `/api/auth/me`（影子用户会被 403）。

## 产品优化方向（2026-10-25 梳理，按优先级）

第一档（不做就很难真正交给用户用）：
1. **保存项目**：现在刷新就全丢（AI 配的卡花过额度）。先做浏览器本地自动保存 + 打开时恢复；口播视频存不了（不上传），重开时按文件名提示他重新选。之后再做服务端「我的项目」。
2. **没有字幕就用不了**：浏览器里只抽音频交给语音识别出字幕；另外放一个示例项目（示例视频 + 字幕），第一次打开点一下就能体验配卡和导出。
3. **字体内置**：服务器上没有苹方，线上导出的字和预览不一样。上线前必须把开源字体（思源黑体 / 思源宋体 / Fraunces 等）放进项目，预览和导出用同一套。
4. **接入商业化**：首页入口、C 端 key 扣点（AI 配卡 / 导出按秒）；导出改成排队 + 进度 + 导出记录（现在一次只能导一个，第二个人直接 429）。

第二档（明显提升效率和成品质量）：
5. **一键换卡型**：同名字段自动带过去，不用删了重加。
6. **单张卡的 AI 操作**：重配这一张 / 缩短文案 / 换个说法。
7. **编辑效率**：框选多张一起移动、复制粘贴、方向键微调、批量改样式。
8. **品牌套件**：B 端上传 Logo / 品牌色 / 字体生成专属主题。

第三档（长期打磨）：
9. **用数据改进 AI 配卡**：记录 AI 配的卡被删 / 改 / 换卡型的比例，定位哪种卡总配错。
10. **卡片库运营**：按使用量精简，默认只展示「常用」。
11. **性能**：只让正在播的卡按 t 重算（现在所有卡每帧都算），卡多了编辑页会卡。
12. **可选导出成片**：上传口播视频直接出成片，给不用剪映的人；代价是存储和渲染压力。
- **B-roll 场景（`data.scene = true`）铺满画布、自己画背景（`SceneBackdrop`），舞台不缩放、不套 `FullFrame`；编辑页 / 调试台 / 导出渲染页三处都要认这个标记。**
  漏认一处的话那一处会把场景当成普通卡缩放摆放，导出和预览不一样。场景会盖住下面轨道的卡：被上层全屏画面（全屏卡 / 场景）整段盖住的卡在
  `dataProblems` 里标红，不然时间轴上一切正常、画面里那张卡根本看不见。
- **场景里的图标只认 `iconLibrary.ts` 里的关键词（Lucide 图标 + 中文关键词），对不上的画虚线问号、check 报出来。** 让 AI 或用户直接写 Lucide 图标名的话，
  编一个不存在的名字那个位置就是空的，不报错。以后给 AI 配场景时同一份关键词表发给它、服务端逐个核。`lucide` 里有个图标叫 `Map`，导入时要改名（会遮住 JS 的 `Map`）。
- **插画类场景里 SVG 元素的旋转缩放一律用 SVG 的 `transform` 属性，不用 CSS `transform`。** SVG 里 CSS transform 的旋转原点
  （transform-box / transform-origin）各浏览器不一致，花瓣会绕错点转：预览看着对，无头浏览器导出时花瓣散到别处，而导出照样「成功」。
- **2026-10-25：第一版 4 个 B-roll 场景（图标概念 / 数据大屏 / 人物上楼梯 / 花朵绽开）作者看过后效果不满意，已全部删掉。** 场景底座保留：
  `data.scene` 的渲染路径（编辑页 / 调试台 / 导出渲染页）、`SceneBackdrop`、`sceneBase`、`iconLibrary` + `SceneIcon`（Lucide）、「被全屏画面盖住」的检查。
- **卡片里不许用 `backdrop-filter`（毛玻璃）。** 导出的是透明叠加层，渲染时卡片后面没有口播画面：预览里毛玻璃把后面的人脸糊掉、字很清楚，
  导出到剪映里人脸清晰地从半透明底板后面透出来，整张卡发虚（作者实测）—— 导出不报错。底板要「实」，不透明度由主题 `--panel` / `--stamp-bg` 定（≥0.78）。
- **声波过渡（`soundwave`）的阶段按总时长的比例排（扫光 0–18% / 起波 12–45% / 峰值 45–60% / 衰减 65–90% / 收束 88–100%），拉长时长 = 整体放慢。**
  光晕、全屏背景里的光团都跟着所选配色走（`--glowc` / 局部覆盖 `--accent`），写死成主题色的话青蓝声波外面一圈橙光。遮挡模式在峰值铺满整屏，用来盖剪辑点。
- **逐条出现时间（`data.cues`，见 `cues.ts`）：多条内容的卡里第 i 条相对卡片开始的秒数，null = 默认节奏。时间一律由代码定（按字幕对齐 / 播放头「当前」/ 时间轴拖菱形），不交给模型。**
  按字幕对齐 = 按顺序往后找「这句字幕里有这一条」的那句，取它的开始时刻；找不到的说出来、保持默认。AI 配的清单放上来时自动对齐一次（条目本来就摘自原话）。
  有一条在卡片结束之后才出现 = 那条出不来，`dataProblems` 标红并给「把卡片延长到够用」。已接：要点清单 / 步骤 / 时间线 / 排行榜 / 气泡 / 两栏对比（先左栏再右栏）/ 对话（cue = 气泡冒出来的时刻，「正在输入」在它前面）/ 柱状图 / 图片组（空位也占一个下标）（模版上的 `cueTargets` / `defaultCue`），
  别的卡要接时三处一起改：组件里每条的出现时刻改成 `cueAt(...)`、`minDuration` 按最晚那条算、`templates.ts` 给 `cueTargets`/`defaultCue`。
  **跟着「上一条」走的东西也要改成跟 cue**（步骤的连线、时间线的横线、最后一个节点亮起）：还按固定间隔算的话，线早早画到一个还没出现的节点上，或者人已经说到了线还没到。
  柱顶数字这类「跟着这一条」的附属元素也要跟 cue 淡入，不然间隔一拉长，还没出的柱子上先挂着一个「0万」。
  **排行榜的 cues[k] 是第 k 个揭晓的（k=0 = 最后一名）**，和 `cueTargets` 的顺序一致：按名次编号的话按字幕对齐是顺着往后找，第 1 名先被找到、最后一名就找不到了。
- **词槽轮换（`slotcycle`）的节奏常量 `SLOT_START / SLOT_STEP` 在 `SlotCycleCard.vue` 和 `templates.ts` 各有一份，两边必须一致。** 调试台关键帧、最短停留、
  默认 cue 都按 templates.ts 那份算；只改了卡片里的节奏的话，「停住」那一格拍到的还在翻词，最短停留也短了，结论一落地就出场。胶囊宽度按隐藏占位量出来的各词宽度插值，
  卡片尺寸按最长那个词撑（同「尺寸按终值量」）。
- **标题降格成标签（`titledemote`）是 `data.scene` 铺满画布（位置按 `--cw/--ch` 算）但带 `seeThrough`：「被全屏画面盖住」的检查不算它。** 漏了 `seeThrough` 的话，
  它挂着的那一整段里下层每张卡都标红「被盖住」，而画面上它们看得清清楚楚。编号和章节标题一样由代码给（`NUMBERED` / planService 里各类各数各的）。
- **五选一（`choose`）的选中项前端按一字不差认，服务端核原话按去标点小写比 —— 服务端放行时把 `pick` 换成候选原文（有测试）。** 不换的话模型写 `premiere`、
  候选是 `Premiere`，卡片上一个都没被选中，读起来像「还没选」。
- **节奏要被调试台 / 最短停留用到的卡，节奏常量单独放一个 ts 让卡片和 `templates.ts` 共用（`pictogramTimes.ts` / `retypeTimes.ts`），别在两边各写一份。**
  各写一份时改了卡片里的节奏、templates.ts 没跟着改，「停住」那一格拍到的还没点亮完 / 还在打字，最短停留也短了，后半段一闪就出场。
- **数字带趋势（`metric`）的大数字就是最后一个点、涨跌箭头按首尾比，都由代码从 `rows` 里取，不另开字段给模型填。** 另开一个「大数字」字段的话，
  模型填的数和折线最后一个点可以对不上，两边各自都核得过原话，读起来完全正常。
- **画面标注（手绘圈 / 双箭头 / 准星 / 引出线，一个 `AnnotateCard` 按 `data.shape` 分）只能手动加（`MANUAL_ONLY`），而且都要列进 `MANUAL_ONLY`。** 位置只有他知道；
  漏列的话上线之后 AI 配卡的 notes 里每次都多一句「已上线但还不支持 AI 配」，读起来像是待办，其实永远不会支持。时间轴上卡片的颜色按 `LIB_CATEGORIES` 的下标取（`cat-N`），
  加分类时 BrollPage 里那几行颜色要一起挪，不然后面几类整体错一个颜色。
- **截图上的位置（放大镜对准哪 / 长截图停在哪）用 `points` 字段在编辑面板里点图定，存占图宽高的百分比；卡片按图的真实宽高比换算（`useImageAspect`），图没加载出来之前不按猜的比例画。**
  按猜的比例画的话放大镜里是旁边那一块、停靠处偏一截，而卡片照样「对准了」。`<img>` 必须一直挂在 DOM 里：导出渲染页靠 `querySelectorAll('img')` 等图加载完，
  用 `v-if` 等比例算出来再挂的话渲染页等不到它，第一帧拍到的是空窗口。长截图的停靠处按从上到下排序，`cues[i]` 对应排好之后的第 i 处（卡片和 templates.ts 都按排好的算）。
- **图片组的「卡堆扇开」（`entrance: 'fan'`）是整叠一起动的，总按错落叠放的槽位画，不认逐张时间；设了 cues 时 check 要说「不生效」。** 不说的话他在时间轴上拖了半天菱形，画面一点没变。
  新闻卡上桌的红线是**语义色**（划重点 = 红），不跟主题强调色走；前后滑动分屏按「之前」那张的比例画框，两张构图不同的话分割线两边对不上，这个代码判断不了，只写在面板标签里提醒。
- **`color-mix()` 只能拿纯色主题变量调（`--accent` / `--ink-on-accent` / `--fg` / `--shadow-c` …），不能拿 `--panel` / `--tile` / `--full-bg`：那几个是渐变。**
  拿渐变调的话整条 `background` 失效、那一层直接透明，不报错 —— 色块扫屏第一版就是三层只剩顶层一种颜色，看起来像「本来就一层」。
  色块扫屏（`shapewipe`）盖满整屏的那段在总时长的 45%–58%，剪辑点放卡片正中；只能手动加（AI 不知道剪辑点在哪）。
- **墨渗转场（`inkbleed`）的毛边 = SVG `feTurbulence` 噪声位移，种子写死、位移量只由 t 算；盖满那一段不挂滤镜，直接铺实色。** 用随机种子的话导出逐帧毛边乱跳；
  盖满时还挂着滤镜的话边缘有亚像素抖动，「停住」那段一直在微微动。滤镜 / 遮罩 id 每张卡各用各的，撞了的话同一画面里的第二张拿第一张的形状画。
  只能手动加（同色块扫屏：AI 不知道剪辑点在哪），剪辑点放卡片正中。洇开曲线用先慢后快再收：前快后慢的话不到四分之一就盖得差不多了，看不出墨在「走」。
- **叙事转折（`turn`）的 `cues[0]` 是「后一句出现」的时刻，不是翻色时刻；翻色由代码往前推 0.48 秒（`turnTimes.ts`）。** 按字幕对齐是拿 `cueTargets` 的文字去字幕里找，
  写成「翻色」这种不在字幕里的词的话，每次 AI 配完都报一句「没在字幕里找到：翻色」，而且永远对不上那个「但」。两句不做交叉淡化、中间留空档：叠着的那几帧读起来像字幕串了。
  底色只在 `--fg` 和 `--full-bg` 之间翻（两种主题下正好一深一浅），所以纸感主题下是「深 → 浅」，和橙夜反过来，这是对的。
  默认透明底（`bg: 'clear'`），转折靠「柔光压成余晖 + 后一句换强调色」；它算不算「盖住下层卡」由模板的 `seeThrough(data)` 按 `bg` 判断 ——
  写死在 defaults 里的话切到整屏底色之后下层卡明明被盖住了也不标红。透明底时字的阴影要并进内联的 `filter`（写在 class 上会被 blur() 整条盖掉）。
- **斜切色块标题（`slab`）的重点字一定等色块到位那一帧才出（`slabLand`）。** 字先在的话前几帧字压在半块色上，读起来像描边坏了。
  它和关键词大字字段几乎一样，AI 那边靠 `when` 分开：有「话题 + 很短的结论」两截的才用它。对句反色（`altlines`）同理要和正误对比 / 删除线改写在 `when` 里分开，不然模型挑卡时三张来回换。
- **章节目录高亮（`agenda`）「现在第几条」只由他在面板里选，AI 配卡不填这个字段（配出来都是「不高亮」的报目录）。** 交给模型的话它数错一条，亮的就是另一章，读起来完全正常。
  选的条数超过实际条数时 check 要说「现在一条都不亮」，不悄悄不亮。
- **增长爆框（`breakout`）的最后一项必须比前面最大的大 1.5 倍以上（check 报）。** 不够的话柱子冲不出框，画面就是一张普通柱状图、而卡名叫「爆框」；刻度由代码取整（1/2/2.5/5×10^k），不交给模型。
  新卡解析「名字 数值」走 `rows.ts` 的 `parseRows`：读不出数的那项是 `NaN`（画 `?` + check 报），不当 0 —— 当 0 的话柱子 / 背面数字是一个看起来正常的 0。
- **字里透图（`textmask`）的图在字里是 `background-clip: text` 画的，同一张图必须另挂一个 `<img>`（就是结尾铺满那层）。** 导出渲染页只等 `<img>` 加载完；只有背景图的话导出前几帧字里是空的，预览一切正常。
- **两图对焦切换（`rackfocus`）清楚的那张始终压在上面（转焦过半时换上下）。** 不换的话焦点转到第 2 张之后，糊掉的第 1 张还挡着它一大块，读起来像「还没切过去」。
  扫描标注（`scanmark`）的点按从上到下排序、标签按排好的顺序对应（同长截图慢滚）；状态条放在截图窗外，放在窗里右上角会压住贴右上角的那个框。
- **整屏场景能不能算「盖住下层卡」由模板的 `seeThrough(data)` 判断（叙事转折、关键词穿越的透明底），没有这一项才看 `data.seeThrough`。** 字里透图即使透明底也不算透（结尾整屏是图）。
